формализацией — **чтобы не писать в Lean то, что уже написано**; затем смотреть, из каких

## Главное: `Zeta23/LinAlg/` — готовый слой, которого у нас нет

Семь файлов, ζ-free, чистая линейная алгебра эрмитовых матриц:

| файл | строк | что там |
|---|---|---|
| `PosIndex.lean` | 127 | `posIndex`, `negIndex`, **`posIndexAbove θ`** |
| `Inertia.lean` | 138 | `posIndex_conj_le`, `posIndex_add_le` |
| `Sylvester.lean` | 309 | `hermForm_*`, `finrank_le_posIndex_of_posDefOn`, `posDefOn_range_hermPosPart` |
| `RankTrace.lean` | 267 | `sum_sq_lower_of_card_pos_le`, `trace_mul_nonneg_of_posSemidef`, `frobSq_add_hermitian` |
| `VonNeumann.lean` | 204 | `vonNeumann_trace_ineq`, `re_trace_mul_eq_eigenvalue_bilinear` |
| `Weyl.lean` | 136 | **`weyl_posIndexAbove_le`**, `cauchySchwarz_count` |
| `HermitianPosPart.lean` | 204 | `specMap_*` — функциональное исчисление на спектре |

Определения дословно:

```lean
def posIndex      (hA : A.IsHermitian) : ℕ := #{i | 0 < hA.eigenvalues i}
def negIndex      (hA : A.IsHermitian) : ℕ := #{i | hA.eigenvalues i < 0}
def posIndexAbove (hA : A.IsHermitian) (θ : ℝ) : ℕ := #{i | θ < hA.eigenvalues i}
```

### Почему это прямо наш случай

**`posIndexAbove θ` — счётчик собственных значений выше порога.** Вердикт
`PROSHKA_VERDICT_GLOWER_TAIL_THEOREM_AND_HEAD_DRIFT_2026-08-10` держит в резерве
`Re-representation 2 — Birman–Schwinger inertia at c₀`, описанную как «counts eigenvalues
below `c₀` without certifying tiny separations». В этих терминах это
`Fintype.card n − posIndexAbove hA c₀`.

То есть инструмент, который у нас числится как незапущенный резервный план, **уже
определён и обвязан леммами** в чужом дереве.

**`weyl_posIndexAbove_le`** (`Weyl.lean`) — неравенство Вейля для этого счётчика при
возмущении. Наша задача R10/R11 ровно про возмущение `B − H`: как меняется спектр при
вычитании поправки.

**`posIndex_eq_rank_of_posSemidef`** (`PosIndex.lean`) — для PSD-матрицы положительный
индекс равен рангу. Наши сертификаты производят именно PSD-факты.

**`frobSq_hermitian_eq_sum_sq_eigenvalues`** и `rtrace_eq_sum_eigenvalues` — след и норма
Фробениуса через собственные значения. У нас эти величины считаются численно и не связаны
с Lean никак.

**`specMap_*`** (`HermitianPosPart.lean`) — функциональное исчисление на спектре эрмитовой
матрицы. Это машина для `B^{−1/2} H B^{−1/2}`, то есть для нашего `rho`, который сейчас
существует только как численная диагностика по серединам.

## `ZeroSide.lean` — структура, которая у нас уже есть

Файл объявляет себя ζ-free и работает с абстрактной конфигурацией:

```lean
structure ZeroBlockData (ι d : Type*) where
  m : ι → ℕ ; one_le_m : ∀ z, 1 ≤ m z
  v : ι → d → ℂ                       -- векторы оценки
  σ : ι → ι ; σ_invol : Function.Involutive σ
  m_σ : ∀ z, m (σ z) = m z
  v_σ : ∀ z, v (σ z) = star (v z)
```

Плюс общие леммы, которых нет в Mathlib: `rank_add_le`, `rank_sum_le`,
`posIndex_le_rank`, `posIndex_sub_le_rank`, `posIndex_neg_eq_zero_of_posSemidef`,
`card_eq_onLine_add`.

**У нас такая структура есть:** отражение `J` с `J² = I`, коммутация `JK = KJ`, разложение
на чётный и нечётный блоки — проверено в Phase 0 до точного нуля на четырёх парах
(`PHASE0_RESULTS_2026-08-07.md`, R1). Значит инстанцировать `ZeroBlockData` нашими данными
возможно; переносить дзета-специфику не требуется, её там нет.

## Как этим пользоваться — порядок, а не список

Владелец сформулировал схему: разложить нужное утверждение на компоненты, для каждой
посмотреть, из каких атомов она состоит, и найти готовые утверждения на тех же атомах.
Практический порядок такой:

1. **Взять незакрытый шаг** из `assembly` (сейчас: `SelectedProjectionTailDecay`, `H2aAt`,
   `c_N_normalizer`, `lagrangeToXi_bridge` — `cheap.py`).
2. **Назвать нужное утверждение** в терминах эрмитовых матриц, а не нашей предметной
   области. Пример: «пол конечного среза» → `posIndexAbove hA c₀ = Fintype.card n`.
3. **Проверить, есть ли оно у них** — `rg` по `Zeta23/LinAlg/`.
4. **Если есть** — не доказывать, а инстанцировать: сформулировать наши данные как их
   структуру и сослаться.
5. **Если нет** — посмотреть, из каких их лемм оно собирается, и достроить недостающее.

**Что этот мост не даёт.** Совпадение атомов и даже совпадение формулировки не означает
применимости: у чужой леммы свои гипотезы. Правило про суррогат по форме действует в полную
силу — рекомендуешь лемму, открой `file:line` и прочитай.

И отдельно: их код под Apache 2.0. Заимствование возможно, но требует указания
происхождения; заимствование **идеи** ничего не требует, но должно быть записано здесь.

## Что не проверено

Прочитаны шапки и списки деклараций семи файлов `LinAlg/`, шапка и секция 1
`ZeroSide.lean`. **Не читались доказательства ни одной из перечисленных лемм**, а также
310 остальных файлов их дерева.

Не проверено главное для инстанцирования: совместимы ли их типовые классы
(`Matrix n n 𝕜`, `RCLike 𝕜`, `Fintype n`) с носителями, в которых живут наши матрицы.
Пока это не проверено, «у них уже есть» остаётся кандидатом, а не фактом.

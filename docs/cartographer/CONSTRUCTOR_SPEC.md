# Конструктор: от незакрытого шага к готовому доказательству

Замысел владельца, 2026-08-11, дословно по смыслу: разложить Lean **полностью до атомов с
описанием, что каждый атом собой представляет**; собрать конструктор, который использует
их репозиторий и наш для построения недостающих теорем или аксиом, закрывающих незакрытые
шаги нашей цепочки; на узлы поставить агентов, понимающих смысл узла, плюс
агента-конструктора, раздающего задания остальным.

Ниже — что для этого нужно, что уже есть и в каком порядке достраивать. Это спецификация,
а не отчёт о сделанном: построен пока только первый ярус.

---

## Схема

Пример владельца: «Кривая». Есть математическое определение → на какие доказуемые
компоненты она разбирается → какие уже доказанные утверждения входят в каждую компоненту.
То же самое для нашей цепочки, только в обратную сторону: от **дыры** к **сборке из
имеющегося**.

```
   незакрытый шаг            что именно требуется доказать
        │
        ▼
   ПЕРЕВОД                   формулировка в терминах, где предметная область не мешает:
                             не «пол odd-сектора ячейки m=13», а
                             «posIndexAbove hA c₀ = Fintype.card n»
        │
        ▼
   ДЕКОМПОЗИЦИЯ              на какие компоненты распадается утверждение
        │
        ▼
   АТОМЫ                     из каких внешних опор состоит каждая компонента
        │
        ▼
   ПОИСК ПО АТОМАМ           какие готовые утверждения — наши, Mathlib, чужие —
                             стоят на тех же атомах
        │
        ▼
   СБОРКА                    что из найденного применимо; чего не хватает — то и есть
                             настоящая новая теорема
```

Ключ в переводе. Пока шаг назван на нашем языке, он несравним ни с чем; названный в
терминах эрмитовых матриц, он попадает в общий словарь с Mathlib и с чужим деревом.

## Ярус 0 — словарь переводов  ✅ заведён, пополняется

`docs/cartographer/TRANSLATION_DICTIONARY.md`

Для каждого незакрытого шага — его формулировка в терминах, общих с Mathlib. **Поставлен
первым по итогу пробного прохода 2026-08-11**: до перевода шаг несравним ни с чем, и ни
агентам нечего раздавать, ни `comparator`-у нечего сверять.

Первая запись — `H2aAt`, числившийся как `GAP`.

**Исправлено 2026-08-11 после вердикта Прошки и прогона.** В первой редакции здесь стояло
«два из трёх нашлись готовыми, осталось инстанцирование, а не новая математика». Оба
сопоставления оказались неверны:

- `hbottom` **не** закрывается Mathlib Rayleigh. Rayleigh даёт существование нижней
  собственной пары; `hbottom` при заранее заданном `epsilon` — это сертификат, а
  сертификатов Mathlib не производит. Перепутано было с `heig`.
- `hsimple` **не** поставляется чужим `Inertia.lean` напрямую и вдобавок невидим: ноль
  импортов `Zeta23` в дереве Q3.

Что действительно подтвердилось прогоном — переходник носителя (матрица → евклидов
оператор, один терм) и подъём ℝ→ℂ (шесть строк). Настоящий остаток — конкретный
penalty-сертификат для CCM-семьи, и это **новая работа, а не инстанцирование**.
Подробности: `probes/PROBE_H2A_RAYLEIGH_TYPED_BRIDGE_2026-08-11.md`.

## Ярус 1 — атомы с описанием  ✅ построен

`docs/cartographer/atom_describe.py`

Для каждого атома из `knowledge.db` находит объявление и извлекает: `file:line`, вид,
сигнатуру, докстринг, namespace. Источники в порядке приоритета: Mathlib на диске → наше
дерево → чужое (`--foreign`).

```bash
python3 docs/cartographer/atom_describe.py --limit 0 \
    --foreign /mnt/hdd01/Soft/GitHub/zeta-23-lean \
    --json docs/cartographer/atoms_described.json
```

**Зачем.** Без описания атом — строка; его нельзя ни сопоставить с чужой леммой, ни отдать
агенту как задание. С сигнатурой и докстрингом это утверждение, о котором можно рассуждать.

**Грабли, уже пойманные.** Первая версия искала по базовому имени и брала первое
попадание: `Real.pi` находился как произведение непрерывных отображений из
`ContinuousMap`, `Complex.exp` — как степенной ряд. Теперь для каждого кандидата
восстанавливается namespace-стек и полное имя сверяется. **Правдоподобно неверный ответ
хуже отсутствия ответа** — это касается и всех следующих ярусов.

**Побочный результат, который важен сам по себе:** атомы со статусом `UNRESOLVED` — это
дыры нашего разбора. На пробной выборке их пятая часть.

## Ярус 3 — перевод как процедура  ◐ делается вручную, инструмента нет

Вход: незакрытый шаг из `assembly` (сейчас `SelectedProjectionTailDecay`, `H2aAt`,
`c_N_normalizer`, `lagrangeToXi_bridge` — см. `cheap.py`).
Выход: формулировка в терминах, общих с Mathlib и чужим деревом.

Это **суждение, а не поиск**: машина не решит, что «пол конечного среза» стоит переводить
как утверждение о `posIndexAbove`. Здесь и нужен агент, понимающий смысл узла.

### Обязательное правило яруса: формулировка копируется, не пишется

**Цель никогда не формулируется из головы.** Она берётся дословно из сигнатуры
потребителя, а тип предполагаемого поставщика — из вывода `#check`. Порядок:

```
1. найти потребителя шага                     (assembly / knowledge.db → file:line)
2. выписать нужную гипотезу ДОСЛОВНО из его сигнатуры,
   вместе с обстановкой файла (`open`, `open scoped`, локальные нотации)
3. #check предполагаемого поставщика → точный тип с implicit-биндерами
4. и только теперь сверять — глазами, потом компилятором
```

Правило родилось из промаха `exact?` 2026-08-11 и подтверждено дважды на прогонах:

- прогон №1: у потребителя `hbottom` записан матрично (`x ⬝ᵥ M *ᵥ x`), а сочинённая форма
  `⟪Ax,x⟫ ≥ λ₀‖x‖²` дала промах при полностью живом механизме;
- прогон №2: `(Q i).PosDef` над ℂ не элаборируется без `open scoped ComplexOrder
  MatrixOrder` — пункт 2 не зря говорит «вместе с обстановкой», обстановка тоже
  копируется.

**Следствие за пределами конструктора.** То же правило снимает зарегистрированную «самую
вероятную точку провала» backtest-капсулы: `exact_statement` капсулы **копируется** из
вывода `#check` по сигнатуре потребителя и никогда не реконструируется вручную. Поле
капсулы ведёт Codex по своей цепи.

Проверяемое требование к выходу: перевод годится, если по нему `rg` находит кандидатов
хотя бы в одном из трёх деревьев.

### Класс дефекта, который ярус обязан ловить: потерянное имя

Карта прогона №1 несла `hermfact1` как имя доказанного входа. Имени **нет в дереве ни в
одном коммите** — ни в объявлениях, ни в сообщениях коммитов, ни в `MAP.md`: это
разговорная кличка блока «эрмитовость ⇒ вещественные нули», прилипшая из старых чатов.
Сам блок при этом существует целиком и разложен на три настоящих адреса
(`ccmWeilMatFinite_transpose_eq` :239, `zerosRealOn_of_hermitian_charpoly_mul` :31,
`posDefSelfAdjoint_exists_hermitian` :18).

Поймано дисковой проверкой за день. Это ровно та поломка, ради которой ярус и строится:
имя, которое все узнают и никто не может открыть.

## Ярус 4 — сборка и раздача заданий  ⬜ не построен

Замысел владельца: агент-конструктор держит цепочку целиком, видит дыры и раздаёт задания
узловым агентам; каждый узловой знает смысл своего узла и умеет искать по атомам.

Что уже есть для этого:

- `cheap.py` — очередь незакрытого **по цене**, с породой шага (`ПЕРЕХОДНИК`, `ПОДЪЁМ
  ИЗМЕРЕНИЯ`, `СБОРКА`, `НУЖНА ТЕОРЕМА`) — готовый вход для раздачи;
- `atom_describe.py` — описания, которые можно вложить в задание;
- `foreign_atoms.py` — где искать готовое;
- `knowledge.db` — `kill`, `move`, `journal_entry`: что уже пробовали и чем убито.

Чего нет:

- **проверки, что найденное применимо.** Совпадение атомов и даже формулировки не
  означает применимости: у чужой леммы свои гипотезы, а типовые классы (`Matrix n n 𝕜`,
  `RCLike 𝕜`) могут не совпасть с нашими носителями. Это должен решать не поиск, а
  компиляция.
- **`comparator`** — механизма «доказано ли заявленное». У Anthropic утверждения записаны
  отдельными файлами-заявками с заглушкой и сверяются внешним инструментом. У нас
  `72` объявления `axiom` (см. `scripts/check_axioms.sh`), и отличить честное допущение от
  подмены нечем.

**Порядок достройки, исправлен дважды 2026-08-11.** Сначала было `comparator` → раздача;
потом словарь → `comparator` → раздача. После вердикта Прошки и прогона порядок такой:

```
точно типизированная цель (списана с потребителя, тип через #check)
  → отбор (exact?/apply?)          — слой полноты, НЕ судья
  → явный терм                     — единственное доказательство
  → отрицательный контроль         — обязателен, иначе «работает» непроверяемо
  → аудит аксиом
  → типизированный дамп окружения
  → comparator
  → раздача заданий
```

Два изменения против прежнего порядка, и оба вынужденные.

**Отрицательный контроль поднят в обязательные.** Прогон, показывающий только успехи, не
отличает работающий отбор от отбора, закрывающего что угодно. Саженец — произвольная
несимметричная матрица — обязан быть отвергнут; ноль на выходе означает
`ОТРИЦАТЕЛЬНЫЙ КОНТРОЛЬ НЕ СРАБОТАЛ`, а не успех.

**Долг перед первой раздачей заданий: дискриминационный тест 046.** Саженцы прогонов 1–3
проверяли отбор на заведомо *чужом* объекте (несимметричная матрица). Не проверено
другое — отличает ли конструктор **похожую, но более сильную** обёртку от заявленной.
Перед тем как впервые раздать задания агентам, скармливается такая обёртка и требуется
`REJECT`. Пока тест не пройден, раздача не начинается: без него агент, подменивший
утверждение на более сильное соседнее, пройдёт как успешный. Долг зарегистрирован Мифосом
2026-08-11 и относится к ярусу 4; ручные прогоны с компиляцией он не блокирует.

**Дамп окружения поднят из отложенных в необходимые.** Прогон 2026-08-11 показал: `exact?`
промахивается по цели, которая является дословным экземпляром заключения леммы, при
гипотезе в контексте — тогда как тот же терм в одну строку её закрывает. Библиотечный
поиск даёт ложное «поставщика нет» при существующем поставщике, значит слоем отбора он
быть не может.

Оговорка о подменах остаётся в силе: конструктор, раздающий задания без сверки результата,
производит правдоподобные подмены быстрее, чем мы успеваем их ловить.

## Что этот конструктор не может дать

Он ищет и сопоставляет — он не доказывает. Найденный кандидат остаётся кандидатом до
прогона Lean; правило про суррогат по форме («рекомендуешь — открой `file:line` и прочитай
докстринг») действует на каждом ярусе.

И отдельно: чужое дерево под Apache 2.0. Идея заимствуется свободно, код — с указанием
происхождения.

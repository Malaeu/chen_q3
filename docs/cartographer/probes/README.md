# Пробы конструктора

Проба — **однократный опыт с зарегистрированным исходом**, а не библиотека и не часть
сборки. Она не импортируется никем, в `lakefile` не входит и живёт ровно затем, чтобы
утверждение из разбора можно было перепроверить, а не принять на слово.

## Как прогнать

Все пробы гоняются из каталога Lean-проекта, путём наружу:

```bash
cd q3.lean.aristotle
lake env lean ../docs/cartographer/probes/<файл>.lean
```

**Пакет обязателен.** Из корня репозитория подхватывается тулчейн `v4.22.0` вместо
`v4.26.0`, и проба падает с `unknown module prefix 'Mathlib'`. Это не мелочь удобства:
кандидат считается применимым только после проверки в пакете потребителя.

Логи прогонов в дерево **не попадают**: `.gitignore` глушит `*.log` глобально, и рядом
лежащие `.log`-файлы существуют только на машине, где пробу гоняли. Искать их в репозитории
бессмысленно. Ожидаемый вывод каждой пробы поэтому записан **в шапке самого файла** — это
и есть носитель ожидания, а не лог.

## Пробы, которые ОБЯЗАНЫ ругаться

Часть проб фиксирует отрицательный результат, и чистая компиляция для них — **провал**,
а не успех. У каждой такой пробы ожидаемый вывод записан в шапке файла. Отсутствие
ожидаемых ошибок означает, что поведение изменилось и наблюдение надо перепроверять.

## Чего пробы не доказывают

Ни одна из них не закрывает `H2a` и не переносится в дерево как теорема. Скомпилированный
терм в пробе означает, что **связка типов работает**, — и ничего о том, что нужный
математический вход у нас есть. Разрыв, оставшийся после всех трёх прогонов, назван в
`../TRANSLATION_DICTIONARY.md`, запись `hfactor`.

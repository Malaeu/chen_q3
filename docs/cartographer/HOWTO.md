# Картограф — что построено и как этим пользоваться

Состояние на 2026-08-10. Все числа ниже — замеры этого дня; расходятся с деревом
через неделю, поэтому старт сессии за ними следит (см. «Когда инвентарь протухает»).

Четыре скрипта живут в `docs/cartographer/` и считают пути **от собственного
расположения**. Запускать из корня репозитория, ничего не настраивая — работает
на обоих телах одинаково.

---

## Зачем это было

Забытую теорему `H2aPenaltyCoercivity` нашёл случайный четырёхагентный картограф,
запущенный обновить устаревшую карту. Искали не её — наткнулись.

Разбор показал: каталог **полон**, но заведён **по имени**. Найти можно, только
зная имя. А спрашивают иначе: «чем закрыть зазор», «откуда взять сертификат»,
«что мешает».

Ящик по именам есть. Ящиков по нуждам не было.

---

## Четыре инструмента

```bash
python3 docs/cartographer/brief.py            # состояние графа из базы
python3 docs/cartographer/cheap.py            # очередь незакрытых шагов ПО ЦЕНЕ
python3 docs/cartographer/inventory.py        # пересобрать инвентарь объявлений
python3 docs/cartographer/atoms.py <out.json> # внешние атомы Mathlib
```

| скрипт | что отвечает | пишет |
|---|---|---|
| `brief.py` | что закрыто, что нет, по цепочкам | ничего (в stdout; файл — только с `--out`) |
| `cheap.py` | что дешевле всего закрыть следующим | ничего |
| `inventory.py` | какие объявления есть, где и покрыты ли индексом имён | `inventory_RouteB.json` рядом с собой |
| `atoms.py` | на чём стоят доказательства | в путь из первого аргумента, иначе `atoms.json` в текущей папке |

`atoms.py` и `cheap.py` читают `inventory_RouteB.json`, который делает `inventory.py`.
Файл лежит в репозитории, поэтому после `git pull` всё работает сразу.

`inventory.py` агентов не запускает — он обязан быть воспроизводимым.

### Самый полезный — `cheap.py`

Он сортирует незакрытое **по цене, а не по номеру**. Порода шага определяется
структурно — тем, ГДЕ существуют упомянутые объекты, а не словами в комментарии:

```
объект есть в Mathlib, у шага нет поставщика   -> ПОТЕРЯННОЕ ИМЯ    минуты
объект уже закрыт READY-шагом другой цепочки   -> СВОЙ ФАКТ          минуты
все объекты наши и существуют в inventory      -> ПЕРЕХОДНИК         часы
поставщик не .lean (JSON/лог)                  -> ПОДЪЁМ ИЗМЕРЕНИЯ   недели
объектов нет ни в inventory, ни в Mathlib      -> НЕНАЙДЕННЫЙ        ???
```

Очередь на 2026-08-10: `ПЕРЕХОДНИК` 5 · `ПОДЪЁМ ИЗМЕРЕНИЯ` 3 · `СБОРКА` 2 ·
`НУЖНА ТЕОРЕМА` 1.

**Инструмент не закрывает шаги.** Кандидат становится закрытием только после
прогона Lean — иначе это суррогат по форме.

`q3.lean.aristotle/aristotle_db/knowledge.db`, замер 2026-08-10:

### Линзы — нужда, сформулированная как затык

| линза | вопрос | записей |
|---|---|---|
| L1 | что даёт отделение, зазор, простоту? | 70 |
| L2 | что даёт положительность, коэрцитивность? | 76 |
| L3 | что переносит конечное в предельное? | 127 |
| L4 | что даёт вещественность, чётность, эрмитовость? | 176 |
| L5 | что даёт оценку с выписанным числом? | 117 |
| L6 | что связывает два языка, отождествляет объекты? | 238 |
| L7 | что принимает данные и выдаёт теорему? | 205 |
| L0 | служебная арифметика | 148 |

Поля: `provides` · `requires` · `strength` (direct / derived / partial) ·
`not_proves` · `fails_if` · `axiom_profile`.

Вопрос «какой контракт задаёт определение» отвечает не линза, а таблица
`contract2` — роли `SLOT` (пустое место), `PREDICATE`, `DATA`, `CONSTRUCTION`,
`ALIAS`, плюс `not_guaranteed`.

### Цепочки сборки

Статусы: `READY` 44 · `GAP` 4 (построить) · `NUMERIC` 3 (нужен прогон) ·
`OWNER_DATA` 3 · `MISMATCH` 1 (обе стороны есть, формулировки разъехались).

## Как спрашивать

Всё через `sqlite3`. **Всегда `?mode=ro`** — Codex пишет в ту же базу.

```bash
DB="file:q3.lean.aristotle/aristotle_db/knowledge.db?mode=ro"

# затык: нужен зазор с гарантией
sqlite3 -separator ' :: ' "$DB" "
  select theorem, file||':'||line, substr(provides,1,80)
  from capability where lens='L1' and strength='direct';"

# затык: чем получить вещественность
sqlite3 -separator ' :: ' "$DB" "
  select theorem, file||':'||line from capability
  where lens='L4' and provides like '%вещественност%' and strength='direct';"

# затык: подать данные и получить теорему
sqlite3 -separator ' :: ' "$DB" "
  select theorem, requires, provides from capability where lens='L7' limit 20;"

# ОСТОРОЖНО: что теорема НЕ доказывает
sqlite3 "$DB" "select theorem, not_proves from capability where not_proves is not null;"

# какая гипотеза прибита контрпримером
sqlite3 -separator ' :: ' "$DB" "select name, protects, hypothesis from counterexample;"

# где пустые места
sqlite3 -separator ' :: ' "$DB" "
  select name, file||':'||line, not_guaranteed from contract2 where role='SLOT';"

# что мешает в цепочке сборки
sqlite3 -separator ' :: ' "$DB" "
  select chain, step, requirement, status from assembly where status!='READY';"

# самые универсальные — попавшие в несколько линз
sqlite3 -separator ' :: ' "$DB" "
  select theorem, count(*) n, group_concat(lens,'+') from capability
  group by theorem having n>2 order by n desc limit 15;"
```

### Атомы — на чём стоит

**Атом** = лемма, которую вызывают в доказательстве, но которая определена НЕ в
проекте. Для нас — Mathlib. Механика: взять тела доказательств, вычесть свои
объекты из инвентаря, остаток и есть атомы.

```bash
# что откроется, если докажу X
sqlite3 "$DB" "select file from atom_use where atom='tendsto_nhds_unique';"

# на чём стоит конкретный файл
sqlite3 -header -column "$DB" "
  select a.name, a.kind from atom a join atom_use u on u.atom=a.name
  where u.file='ZeroEscapeLogic.lean' and a.kind not in ('TACTIC','TRIVIAL');"

# несущие атомы проекта
sqlite3 -header -column "$DB" "
  select name, kind, n_files from atom
  where kind in ('NONVANISHING','TOPOLOGY','LINALG','ANALYSIS')
  order by n_files desc limit 20;"

# чем работает конкретная ветка (жанр виден по kind)
sqlite3 "$DB" "
  select a.kind, count(*) from atom a join atom_use u on u.atom=a.name
  where u.file like 'D0Pstar%' group by a.kind order by 2 desc;"
```

`kind`: `NONVANISHING` · `TOPOLOGY` · `LINALG` · `ANALYSIS` · `OTHER` · `TACTIC` · `TRIVIAL`.

## Как пересобрать

```bash
python3 orchestrator/backfill_db.py --check       # read-only: разошлись ли Lean и индекс имён
python3 orchestrator/backfill_db.py --sync        # goal-close/явный write-scope: синхронизировать индекс
python3 docs/cartographer/inventory.py            # пересобрать JSON; --scope RouteB по умолчанию
python3 docs/cartographer/atoms.py out.json
```

Прогон 2026-08-10 до ремонта показал 68 «сирот». Это название было неточным:
15 тестов и миграций сюда вообще не входили; все 68 были настоящими Lean-декларациями,
которые старый одноразовый backfill не добавлял после изменения уже известного файла.
Новый синхронизатор сверяет все 194 Route B-файла, добавляет новые декларации и удаляет
протухшие строки. После синхронизации: 1583 объявления, **не в каталоге 0**.
На `GOAL_CLOSE` Spine запускает sync, JSON-инвентарь и индекс внешних атомов одной
зарегистрированной последовательностью; вручную эти три команды нужны только для диагностики.
Музей `PrimeCert` исключается.

Инвентарь коммитится в репозиторий — иначе он не появится на втором теле, а
проверка протухания останется без точки отсчёта.

### Когда инвентарь протухает

Git не хранит связь «этот json порождён из тех `.lean`»: файл не менялся — дерево
чистое, и молчание ничего не доказывает. Даты файлов тоже не годятся — git не
хранит mtime, после клона он у всех одинаковый.

Поэтому `./specs_docs/session_start.sh` спрашивает историю прямо: когда инвентарь
последний раз коммитили и менялись ли `.lean` в RouteB после этого. Разошлось —
старт **падает** с расхождением. Незакоммиченные `.lean` считаются отдельно: `HEAD`
их не видит, а картограф от них уже врёт.

---

## Чего этот инструмент НЕ делает

Не доказывает теорем. Не оценивает, сколько стоит закрыть слот — граф говорит
только, **что обвалится**, не **сколько работы**. Не заменяет чтение файла:
`provides` — это пересказ агента, а не текст Lean; перед применением открывай
`file:line` и читай докстринг.

# ПРОЦЕДУРА — как разбирать вопрос «что нужно, чтобы X»

Порядок отработан 2026-08-08, схлопнул карту вчетверо за один вечер.

```
1. НАЙТИ ВЕРШИНУ        grep по имени цели в Q3/, открыть файл, прочитать сигнатуру
2. СПУСТИТЬСЯ           каждая посылка → чем закрыта; рекурсивно, до упора
3. ЗАМЕРИТЬ АТОМЫ       на каждом этаже: сколько внешних атомов
4. ПРОЧИТАТЬ ПОКАЗАНИЯ  три правила ниже
5. ИСКАТЬ ПАЧКУ         прежде чем считать N обрывов — искать теорему, дающую их разом
6. ЗАПИСАТЬ В assembly  иначе через неделю будем копать заново
```

## Три показания по числу атомов

| наблюдение | вывод |
|---|---|
| **0 внешних атомов** | переходник, не работа. `CCMFiniteWeilRealZeros.lean` — один `simpa using` |
| **аномально много** | труд УЖЕ потрачен, а не предстоит. `GenericZeroTransfer` — 69 атомов при 0 sorry |
| **ветки не делят атомов** | независимы, параллелятся разными людьми |

## Детектор чеков (важнее всего)

**Теорема-импликация с `0 sorry` НЕ закрывает шаг, пока её посылка не обеспечена.**

Это чек: бумага подлинная, банк работает, но пока не принёс условие — денег нет.
Записать такой шаг как `READY` = вписать чек в графу «наличные».

Проверка: у любого `READY` спросить «а вход к нему откуда». Если ответа нет —
это чек. За один вечер поймано дважды в одной цепочке (шаги 9 и 10
`SIMPLE_EVEN_GROUND_TO_REAL_ZEROS`).

## MISMATCH ≠ GAP

```
GAP       трубы нет, надо варить
MISMATCH  обе стороны готовы, разошлись формулировки, нужен переходник
```

Смешивать в одном счёте «шагов до цели» — врать шкалой.

## Собственная ловушка — суррогат по форме

Найти объект правильной ФОРМЫ и достроить применимость самому, не открыв файл.
За вечер случилось трижды; аудит Прошки поймал у себя то же самое
(`PROBE_NOT_SOURCE_TRIAL`: *«numerically extremely close, but different
constructions»*). Лекарство одно: **рекомендуешь X — открой `file:line` и прочитай
докстринг**, прежде чем произносить.

## Внешний observer-контур

`codex_specs/cartographer/` может существовать на конкретной машине как независимая
копия наблюдателя. Она не является входом Codex, не обязана быть byte-identical и
не участвует в strict startup. Для исполнения Codex каноничны только четыре
скрипта из `docs/cartographer/` и репозиторный `inventory_RouteB.json`.

Внешние `load_capability.py`, `load_switches.py`, `load_assembly.py` и их L1--L8
линзы не переносятся в исполнительный контур автоматически: они содержат
machine-local пути и пишут каноническую `knowledge.db`. Их результат допустим
только как отдельно проверенный import packet или после явного порта в репозиторий.

Это сохраняет исходный смысл независимого наблюдателя, но убирает скрытую
зависимость старта Codex от второй директории.

# THREE_BODY_LOOP — контур из трёх тел без ручного погоняния

*Дизайн 2026-08-21 по заказу владельца, после первого независимого аудита Codex.
Ничто здесь не действует, пока владелец не ратифицирует CODEX_GRANT ниже, а
судья не отревизует правку его контроля.*

## Зачем

Трое суток Linux-тело работало одно и накопило пять семантических расхождений,
которые ядро пропустило, потому что все они были в связках и формулировках, а
не в доказательствах. Аудит Codex нашёл их за один заход. Вывод: второе тело
окупается, но только если его не надо каждый раз заводить руками.

## Разделение ролей

```
CODEX    пишет Lean, решает сам, гейтует своим ядром, коммитит, пушит.
         Упёрся в стену → пишет CODEX_REQ_*.md и пушит. НЕ ходит к судье сам.

LINUX    оркестратор. Ловит пуши вахтой, читает запросы, формулирует вопрос
         судье, несёт вердикт обратно, пишет задание, двигает фронт.
         ЕДИНСТВЕННЫЙ с браузером — это его незаменимая часть.

ПРОШКА   судит, убивает, разлагает стены на этажи. Отвечает вердиктом в репо.

ВЛАДЕЛЕЦ границы, ратификации, PX_RH_CLAIM, указатель CURRENT.md.
```

## Такт контура

```
1. CODEX работает, коммитит, пушит                          [CODEX_GRANT]
2. упёрся → docs/routeB_bus/CODEX_REQ_<дата>_<тема>.md, пуш [CODEX_GRANT]
3. вахта Linux видит пуш → будит тело                       [механика]
4. Linux читает запрос, формулирует, пингует судью браузером [NIGHT_GRANT]
5. судья пушит вердикт
6. вахта будит Linux снова
7. Linux пишет docs/Codex/TASK_*.md, пушит                  [NIGHT_GRANT]
8. Linux триггерит Codex                                    ← см. ниже
9. → пункт 1
```

## Триггер — решённый вопрос

```bash
codex exec resume --last "<короткая строка>"      контекст ЦЕЛ, не новая сессия
codex exec resume --last "..." -o /tmp/reply.md   его ответ ложится ФАЙЛОМ
codex exec ... --json                             события построчно
codex exec ... --output-schema FILE               структурированный ответ
```

`-o` важнее, чем кажется: **читать ответ Codex браузер не нужен**, в отличие от
судьи. Значит звено 8→1 полностью механическое.

ОГРАНИЧЕНИЕ, проверено 21.08: если у Codex ЖИВА интерактивная сессия
(`codex --yolo` в терминале), `exec resume` создаёт конкурирующую. Триггерить
можно только когда интерактивной нет. Проверка одной строкой:

```bash
pgrep -f "codex --yolo" >/dev/null && echo "ИНТЕРАКТИВНАЯ ЖИВА — не триггерить"
```

## CODEX_GRANT — манифест на ратификацию

Инстанция того же вида, что NIGHT_GRANT для Linux-тела.

**РАЗРЕШЕНО Codex без per-action OK:**

```
C1  коммит и пуш Lean-источников, прошедших ЕГО СОБСТВЕННЫЙ полный гейт
      (lake env lean + lake build + q3_check, стандартная тройка аксиом,
       sorryAx отсутствует) — с квитанциями blob и sha256 в сообщении коммита
C2  коммит гейт-артефактов CODEX_GATE_*.md и SOURCE RECORD
C3  запись и пуш docs/routeB_bus/CODEX_REQ_*.md при упоре в стену
C4  тактические починки СВОИХ источников: тактики, statement нетронут
```

**ЗАПРЕЩЕНО безусловно, вейвером не снимается:**

```
PX_RH_CLAIM · ROUTE_PROMOTION · мёрж в main · force-push
правки глобальных правил (CODEX_CONTROL, SESSION_ENTRY, CLAUDE.md, контракт)
движение docs/Codex/CURRENT.md — это владельческий указатель
платные вызовы · глубокие прогоны Aristotle
правка чужих источников (Linux, Прошка) без отдельного разрешения
обращение к судье напрямую — только через CODEX_REQ и Linux
```

**Стоп-условия (немедленная пауза до владельца):**

```
красный гейт, не чинящийся тактикой за 2 попытки
расхождение квитанций · конфликт при rebase
чужая незакоммиченная правка в рабочем дереве
strict-валидация spine вернула новое расхождение
```

## Дисциплина Codex — формулировка владельца, записать в шапку каждого задания

> **Сокращай пространство решений, а не расширяй.** Нашёл два пути — убей один
> измерением, а не оставляй оба. Проверяй варианты сам: у тебя есть ядро,
> `./ask.sh` и вся полка. К судье идёшь **только** когда упёрся в стену,
> которую не можешь ни пройти, ни обойти, ни убить. Запрос к судье — признак
> стены, а не способ подумать вслух.

Это ровно то правило, которого не хватало: без него второе тело начнёт плодить
бифуркации и превратит судью в чат.

## Формат CODEX_REQ

Чтобы вахта Linux отличала стену от обычного пуша, файл обязан начинаться с:

```yaml
CODEX_REQ: <дата>-<короткий-slug>
WALL: <что именно не проходит, одной фразой>
TRIED: <что уже попробовано и почему не сработало — НЕ пусто>
NEED: <какое решение судьи разблокирует>
BLOCKS: <какой этаж стоит>
```

`TRIED` пустым быть не может. Это и есть проверка «стена, а не размышление».

## Чего в контуре НЕТ и не будет

Автоматического повышения Route B. Автоматического заявления RH. Автоматической
правки глобальных правил. Триггера судьи мимо Linux-тела. Всё это остаётся за
владельцем, и контур существует, чтобы приносить ему решения, а не принимать их.

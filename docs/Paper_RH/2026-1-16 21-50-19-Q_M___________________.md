## [2026-01-16] THE LOCALIZATION ARGUMENT (Heat Kernel “Blind Spot” at \(\xi=0\))

**Context (why this appeared):**  
In the “CS trap” route, a crude worst‑case bound (saturated by constant-like vectors) makes the prime operator look as if \(\|T_{\mathrm{prime}}\|\) grows like \((2M+1)\), tempting an artificial renormalization factor \(1/(2M+1)\). But renormalizing the prime part changes the Weil functional (i.e. produces \(Q_M\neq Q\)), so it breaks the T5/Weil linkage.

**Core observation (structural, not algebraic):**  
Our Fejér×heat atoms include a Gaussian heat factor that **concentrates near \(\xi=0\)** as the localization parameter increases. Meanwhile, the prime sampling nodes are
\[
\xi_n=\frac{\log n}{2\pi},
\]
so the *first* node is
\[
\xi_2=\frac{\log 2}{2\pi}\approx 0.1103,
\]
and there are **no nodes at \(\xi=0\)**. (This is directly built into the definition of the prime term in \(Q\): nodes \(\xi_n=\log n/(2\pi)\), weights \(2\Lambda(n)/\sqrt n\).)【110:5†RH_Q3.pdf†L2-L14】【110:5†RH_Q3.pdf†L16-L35】

**Mechanism (“blind spot” inequality):**  
If the heat factor is \(G_t(\xi)=\exp(-4\pi^2 t\xi^2)\) (as in the Fejér×heat window), then at the prime nodes
\[
G_t(\xi_n)=\exp(-4\pi^2 t\,\xi_n^2)=\exp\!\big(-t(\log n)^2\big)\le \exp\!\big(-t(\log 2)^2\big).
\]
So **every prime sample is uniformly exponentially suppressed** by the constant \((\log 2)^2\approx 0.48045\).

**Consequence (beats polynomial barriers):**  
For atoms centered near the origin (e.g. \(\tau=0\), or more generally \(|\tau|<\xi_2/2\) with a narrow enough window), the prime contribution is exponentially small compared to the Archimedean contribution. With the common normalization \(\Phi_t(0)=1\), the Arch term decays at worst polynomially in the localization parameter, while the prime evaluations decay like \(\exp(-(\log 2)^2 t)\). Hence
\[
\frac{\mathrm{PrimeTerm}}{\mathrm{ArchTerm}}\;\lesssim\; \mathrm{poly}(t)\,\exp\!\big(-(\log 2)^2 t\big)\to 0,
\]
so any “\((2M+1)\)” inflation coming from worst‑case \(\ell^1/\ell^2\) estimates is irrelevant on these specific localized atoms.

**Quick numeric sanity check:**  
\((\log 2)^2\approx 0.48045\). At \(t=40\): \(\exp(-(\log 2)^2 t)\approx 4.5\times 10^{-9}\).

**Important scope warning:**  
This is a **local** phenomenon tied to the genuine gap \((-\xi_2,\xi_2)\). For atoms centered away from \(0\), the nodes \(\xi_n\) become dense on \([0,K]\) as \(K\) grows, so there is no uniform “blind spot.” Global \(\tau\)-uniform control still needs an RKHS‑type cap (as in the “uniform prime cap” route).【110:6†RH_Q3.pdf†L24-L38】

|\langle p, v_n^{(M)}\rangle|^2 = \frac{|p(\xi_n)|^2}{2M+1}.

\langle T_P^{(M)}1,1\rangle=\frac1{2M+1}\sum_{n\ge2} w(n)\Phi(\xi_n),

а не \(\sum w(n)\Phi(\xi_n)\).

## 3) Самый дешёвый “uniform по M” ремонт (без ухода в \(Q_M\))

Если твоя конечная цель в Lean — **закрыть именно `rayleigh_Q_identification` для `basis0`** и сохранить *uniform*‑цепочку через A3‑bridge, то есть простой трюк, который:

- не трогает нормировку `prime_vec`;
- не умножает арх‑часть;
- не вводит \(Q_M\);
- и **не ломает** бюджет по нормам (потому что добавляет лишь маленький PSD‑ранк‑1).

### Идея: поправить прайм‑оператор ранк‑1 добавкой в направлении `basis0`

Обозначим
\[
S := \sum_{n\ge2} w(n)\Phi(\xi_n).
\]

Тогда из вычисления выше:
\[
\langle T_P^{(M)}1,1\rangle = \frac{S}{2M+1}.
\]

Добавь к прайм‑оператору PSD‑коррекцию
\[
R_M := \Big(1-\frac1{2M+1}\Big)S\;\;|1\rangle\langle 1|.
\]

и положи
\[
T_{P,\mathrm{corr}}^{(M)} := T_P^{(M)} + R_M.
\]

Тогда **на одном** векторе \(1\) (т.е. в Lean на `basis0`) прайм‑квадратичная форма становится ровно правильной:
\[
\langle T_{P,\mathrm{corr}}^{(M)}1,1\rangle
=\frac{S}{2M+1}+\Big(1-\frac1{2M+1}\Big)S
=S.
\]

И значит появляется точная идентификация Weil‑функционала без “ложного множителя на всё”:
\[
\frac1{2\pi}Q(\Phi_{B,t})
=\langle (T_M[P_A]-T_{P,\mathrm{corr}}^{(M)})1,1\rangle.
\]

### Почему это не убивает uniform‑часть

- \(R_M\) — PSD ранк‑1, его операторная норма равна коэффициенту:
  \(\|R_M\| = \big(1-\frac1{2M+1}\big)S \le S\).
- В ваших оценках \(S\) и так контролируется прайм‑cap’ом (RKHS cap), то есть “маленькая константа” — именно для этого cap и нужен.
- Тогда \(\|T_{P,\mathrm{corr}}^{(M)}\|\le \|T_P^{(M)}\|+\|R_M\|\le 2S\), и в бюджете A3‑bridge вы просто заменяете прайм‑cap \(\rho\) на \(2\rho\). При ваших числах это всё ещё сильно ниже символ‑floor, так что запас сохраняется.

Это прямой способ получить **точный** \(Q(\Phi)\) *и* оставить всю архитектуру uniform по \(M\), потому что ты не тащишь \((2M+1)\) внутрь нормы оператора — ты компенсируешь только “не тот коэффициент” на конкретном тестовом векторе, и делаешь это PSD‑добавкой контролируемого размера.

> Если вам принципиально важно не менять определение прайм‑оператора “философски”, то этот шаг можно подать как “корректный объект для Rayleigh‑теста `basis0`”, т.е. как *тестовый* оператор для идентификации Q, а не как основной объект для RKHS‑cap. Но формально в Lean проще просто заменить один объект на другой и обновить пару лемм про норму/PSD.

## 4) Lean‑техника: как закрыть `integral_P_A_eq_arch_term` без tsum/integral ада

Ключевая подсказка прямо в pdf: у \(g_{B,t}^{\mathrm{sym}}\) **компактный носитель** \([−B,B]\), поэтому **периодизация конечна для каждого** \(\theta\):
> “\(g_{B,t}^{\mathrm{sym}}\) is compactly supported on \([−B,B]\), so the periodization sum defining \(P_A\) is finite for each \(\theta\).”【419:0†RH_Q3.pdf†L27-L28】

Это означает: не надо бороться с `tsum` вообще.

### Скелет “лёгкого” доказательства

1) Возьми явную верхнюю границу числа сдвигов:
\[
N := \left\lceil\frac{B+\pi}{2\pi}\right\rceil.
\]
Тогда для всех \(\theta\in[-\pi,\pi]\) и всех целых \(m\) с \(|m|>N\) получаешь
\[
g_{B,t}^{\mathrm{sym}}(\theta+2\pi m)=0
\]
просто по support‑аргументу.

2) Следовательно, на фундаментальном интервале:
\[
P_A(\theta) = 2\pi\sum_{m=-N}^{N} g_{B,t}^{\mathrm{sym}}(\theta+2\pi m),
\]
и это уже `Finset.sum`, без `tsum`.

3) Интегрируй, меняй переменную в каждом слагаемом (`θ ↦ θ+2πm`), получи сумму интегралов по отрезкам \([-\pi+2\pi m,\pi+2\pi m]\).

4) Заметь, что на support’е \([−B,B]\) эти отрезки покрывают всё, а вне support интеграл ноль, поэтому сумма равна \(\int_\mathbb R g_{B,t}^{\mathrm{sym}}\).

Это **в разы** надёжнее по времени, чем `integral_tsum` + Fubini/Tonelli, потому что ты убираешь `tsum` из картины.

## 2) Несостыковка прямо в тексте Rayleigh identification: “\(\Phi(\xi_n)\Phi(\xi_n)\)” vs определение \(Q\)

## 1) Лемма: на фундаментальном интервале `tsum` = `Finset.sum` (униформный Finset)

Цель: не доказывать Summable/Integrable для перестановки \(\int\) и \(\sum'\), а показать, что \(\sum'\) **вообще конечная** на \(\theta\in[-1/2,1/2]\).

### Ровно что надо в Lean

- Вход: `hsupp : Function.support f ⊆ Set.Icc (-B) B`
- Выход: существует `N : ℤ` (лучше взять явно) такой, что для всех \(\theta\in[-1/2,1/2]\)
  \[
  \sum'_{n\in\mathbb Z} f(\theta+n)=\sum_{n\in\mathrm{Icc}(-N,N)} f(\theta+n).
  \]

### Самая лёгкая (и быстрая) реализация

Не делай `∃ N`. Просто **зафиксируй**
- `N : ℤ := Int.ceil (B + (1/2 : ℝ))`
и используй факт `B + 1/2 ≤ (N : ℝ)` через `Int.le_ceil`.

Дальше ключевой “hzero”:

- Пусть `θ ∈ Icc (-1/2) (1/2)` и `n ∉ Finset.Icc (-N) N`. Тогда `n < -N ∨ N < n` (из `¬(-N ≤ n ∧ n ≤ N)`).
- Случай `N < n`:  
  из `B+1/2 ≤ N < n` получаешь `B+1/2 < (n:ℝ)`; вместе с `θ ≥ -1/2` даёт `B < θ + (n:ℝ)` ⇒ \(\theta+n\notin[-B,B]\).
- Случай `n < -N`:  
  аналогично получаешь `θ + (n:ℝ) < -B` ⇒ \(\theta+n\notin[-B,B]\).

А затем:
- из `hsupp` и “\(\theta+n\notin Icc(-B,B)\)” следует `f(θ+n)=0` (через `Function.mem_support` ↔ `f x ≠ 0`).

И только после этого:
- применяешь лемму вида `tsum_eq_sum` (или её вариант) для функций, которые нулевые вне finset.

### Практическая подсказка

Чтобы не тонуть в `abs`/reverse triangle, делай **строго линейные неравенства** как выше (через `θ ≥ -1/2` и `θ ≤ 1/2`). Это в Lean обычно решается 2–3 строчками `linarith`/`nlinarith` без “аналитических” лемм про `abs`.

## 2) Лемма: интеграл периодизации без `integral_tsum_of_summable_integral_norm`

Цель: доказать
\[
\int_{-1/2}^{1/2}\sum'_{n\in\mathbb Z} f(\theta+n)\,d\theta = \int_{\mathbb R} f(x)\,dx,
\]
используя только:
- (а) редукцию к конечной сумме из леммы 1,
- (б) вынесение конечной суммы из интеграла,
- (в) замену переменной \(\theta\mapsto x=\theta+n\),
- (г) готовую разбиение-интеграла лемму `Integrable.hasSum_intervalIntegral`.

### Шаги “как писать в Lean”

Пусть `a := -(1/2 : ℝ)`.

1) **Перепиши integrand как finset sum на интервале**  
Используй `intervalIntegral.integral_congr` или `intervalIntegral.integral_congr_ae` (если удобнее) + лемму 1:
- на каждом `θ` из `Set.Icc a (-a)` у тебя точное равенство `tsum = finset.sum`.

2) **Вынеси finset.sum из intervalIntegral**
Это должно проходить через `simp` (там обычно есть `intervalIntegral.integral_finset_sum`).

3) **Сдвинь каждый член**
Для каждого `n`:
\[
\int_{a}^{a+1} f(\theta+n)\,d\theta = \int_{a+n}^{a+n+1} f(x)\,dx.
\]
В Lean это обычно ровно лемма вида:
- `intervalIntegral.integral_comp_add_right` (или “_left”; смотри `#find` по `f (x + d)`).

4) **Перейди от finset.sum интервалов к tsum интервалов**
Здесь опять используешь “локальную конечность”, но уже для последовательности  
`n ↦ ∫ x in a+n .. a+n+1, f x`.
Покажи: при `|n|` большом отрезок `[a+n,a+n+1]` лежит вне `[-B,B]`, а значит **интеграл ноль**, потому что `f=0` почти всюду на этом отрезке (реально везде).  
Тогда снова `tsum_eq_sum` и всё.

5) **Закрой финал одной строкой**
Берёшь готовый:
- `MeasureTheory.Integrable.hasSum_intervalIntegral (μ := volume) (f := f) (y := a) hint`
и получаешь `(∑' n, ∫_{a+n}^{a+n+1} f) = ∫ f`.

Это полностью избегает swap(∫,∑').

# NIGHT_LOOP_DESIGN — ночная петля Claude↔Прошка без владельца

*Дизайн 2026-08-20 по заказу владельца («я иду спать, а вы хуярите между
собой»). Собран из разведки трёх агентов по диску: аудит петли кондуктора,
аудит каналов, аудит правил. Ничто здесь не активно, пока владелец не
ратифицирует NIGHT_GRANT ниже.*

## Такт петли (один оборот, повторяется ScheduleWakeup'ом)

```
1. fetch: Прошка запушил?            [авто]
     да → гейт (lake + q3_check) → гейт-артефакт → мигратор
          → зеркало локально → scoped-коммит + пуш        [NIGHT_GRANT]
2. харвест браузера: ответ дозрел в чате?                  [авто, read-only
     detect_complete.js, два одинаковых опроса подряд]
3. relay.py route: разбор по маркерам [→PROSHKA]/[→YLSHA]… [авто]
4. очередь: OPEN-запросы висят, судья молчит?
     да → пинок в композер: «смотри очередь REQ-…»         [NIGHT_GRANT,
          свежий чат на транзакцию, оракул композера перед записью]
5. фронт: узел ясен (по счётчику опор + вердиктам), судья свободен?
     да → typed-задание в очередь (W9: CLOSES/OPENS)       [авто-запись,
          наружу едет коммитом п.1]
6. странное/неоднозначное/[→YLSHA]/UNPARSABLE?
     да → СТОП-ПАУЗА петли, всё в утренний отчёт           [fail-closed]
7. спать 20–40 мин, повторить
```

Носитель: /loop (динамический ScheduleWakeup) в живой сессии на этой
машине; Chrome залогинен, чат Прошки открыт. Утром — отчёт: что закрыто,
что запушено (с манифестами), что ждёт OK.

## NIGHT_GRANT — манифест на ратификацию владельцем

Инстанция GOAL_SCOPED_OPERATIONAL_GRANT (CODEX_CONTROL.md §17.3) на ночь,
scope: текущий фронт Route B (Goal058/G6-транзакция и очередь REQ).

**РАЗРЕШЕНО без per-action OK, на ночь:**

```
N1  scoped-коммиты и пуш в rh_clean СТРОГО для:
      гейт-артефактов (LINUX_GATE_*), записей ROUTE_B_STATE,
      knowledge.db (жатва мигратора), статусов REQ в очереди,
      typed-заданий в очередь, зеркала docs/routeB_bus/ + MANIFEST
N2  пинок судьи в композер: ТОЛЬКО строка вида
      «смотри очередь: REQ-<id> [, REQ-<id>]» — не более 4 отправок
      за ночь, свежий чат на транзакцию, оракул композера обязателен
N3  тактические починки его Lean-источников: ТОЛЬКО тактики,
      statement/гипотезы/импорты нетронуты (проверяется diff'ом),
      коммит с полным гейт-выводом в сообщении
```

**ЗАПРЕЩЕНО ночью безусловно (HARD, вейвером не снимается):**

```
PX_RH_CLAIM / ROUTE_PROMOTION / мёрж в main / force-push
правки глобальных правил (CLAUDE.md, протокол судьи, SUPPLIER_CONTRACT,
  CODEX_CONTROL, session_start) — читать можно, менять нельзя
платные вызовы (Мифос и пр.), глубокие прогоны Aristotle
отправка судье ЧЕГО-ЛИБО кроме строки-пинка N2 (батчи-вопросы готовятся
  в очередь, наружу — коммитом; содержание он читает из репо сам)
изменение statement/гипотез в Lean; новые Lean-источники от нашего имени
всё, что легло в [→YLSHA] или UNPARSABLE — только утренний отчёт
```

**Стоп-условия петли (немедленная пауза до утра):**

```
красный гейт, не чинящийся тактикой за 2 попытки · оракул композера
видит «похоже на Ылшу» · любой конфликт при rebase · расхождение
квитанций · session_start вернул новое РАСХОЖДЕНИЕ · подряд 3 пустых
такта (судья спит — не спамить)
```

## РАТИФИКАЦИЯ

**NIGHT_GRANT ратифицирован владельцем 2026-08-20, в чате Linux-сессии.**
Разрешения N1, N2, N3 действуют как записаны. Пограничные позиции решены:

```
(a) пуш ночью gate-verified Lean-источников судьи:  ДА
    — с пометкой ПЕРВОЙ строкой утреннего отчёта
(b) отправка заготовленных батчей текстом в композер: НЕТ
    — содержание только через очередь в репо, пинок указывает REQ-id
```

Активация: владелец запускает петлю командой «ночная петля» (/loop) в живой
сессии с открытым Chrome; остановка — «стоп петля» или любое стоп-условие.
Каждый пуш ночи несёт в сообщении коммита строку `NIGHT_GRANT_2026-08-20`.

## Две пограничные позиции — решались владельцем (исторический раздел)

```
(a) пуш ночью его gate-verified Lean-источников: разведка правил
    говорит — CONDUCTOR требует явного go; включить в N1 или оставить
    утренней очереди?  ПРЕДЛОЖЕНИЕ: включить (это его коммиты, мы
    только гейтуем), но пометить в утреннем отчёте первой строкой.
(b) отправка ЗАРАНЕЕ ЗАГОТОВЛЕННЫХ батчей-вопросов в композер (не
    строка-пинок, а текст): byte-exact правило §4.2 требует показа
    манифеста владельцу. ПРЕДЛОЖЕНИЕ: НЕ включать — содержание едет
    через очередь в репо, пинок лишь указывает REQ-id. Дешевле и чище.
```

## Почему это безопасно (из разведки)

- Прошка и так пушит сам — ночью меняется только то, что его коммиты
  гейтуются немедленно, а не утром.
- Содержание заданий едет через репозиторий (очередь + push), который он
  сам читает при старте (STANDING REPO FETCHES); композер — только звонок.
- Всё записанное append-only (§4b), каждое действие оставляет артефакт,
  утренний отчёт собирается из git-лога и state/log.jsonl, спрятать
  ничего нельзя.
- Fail-closed везде наследуется от кондуктора: «не уверен — не трогай,
  доложи».
```

## ИНСТРУКЦИЯ ПОЛЬЗОВАНИЯ (для владельца; написана после первого живого оборота 2026-08-20)

**Запуск** — одна фраза мне в живой сессии:

```
«ночная петля»        — на ночь
«петля, я отошёл»     — днём на работе: тот же грант, та же механика
```

Условия: Chrome на этой машине залогинен в ChatGPT (проект RH_März_2026),
NIGHT_GRANT действует. Больше ничего не нужно.

**Остановка:** «стоп петля» — либо сама по стоп-условию (красный гейт без
тактической починки, конфликт rebase, оракул видит чужой черновик, 3 пустых
такта подряд). Остановленная петля НЕ теряет работу: всё лежит в репо и
очереди, утренний/вечерний отчёт собирается из git-лога.

**Как это устроено внутри (чтобы не было магии):**

```
вахта = фоновый bash-процесс: раз в 60 сек git fetch;
        хеш origin/rh_clean изменился -> процесс завершается ->
        завершение фоновой задачи САМО вызывает Claude (механика
        харнесса: task-notification) -> такт петли
такт  = pull -> гейт ядром -> артефакт -> жатва мигратором ->
        статусы очереди -> коммит+пуш [NIGHT_GRANT] ->
        пинок в композер ТОЛЬКО если судья свободен и REQ висит ->
        перезавод вахты
потолок вахты 6 ч: истекла пустой -> Claude просыпается и проверяет
        браузер руками (ответ мог остаться в чате без пуша)
```

**Что переживает перезапуск сессии, а что нет:** вахта живёт внутри одной
сессии Claude — новая сессия заводит СВОЮ (эта инструкция + resume-память
говорят ей как). Работа не теряется никогда: состояние в репозитории.

**Пределы за ночь/отлучку:** ≤4 пинка в композер; занятого судью (спиннер/
квадрат-стоп) не пинать — очередь донесёт сама; 36-ошибочный источник не
чинится тактикой — уходит RED-артефактом и REQ-запросом назад судье.

**Полевой урок №2 (вахта №2, тот же вечер):** вахта, сравнивающая «хеш
origin изменился», просыпается на СВОИ ЖЕ пуши — ложный подъём на собственном
коммите инструкции. Правильное условие: `git rev-list --count
HEAD..origin/rh_clean > 0` — origin ОБОГНАЛ локальное HEAD; свой пуш держит
их равными и вахту не будит.

**Полевые уроки первого оборота:** кнопка отправки уезжает при развороте
композера — скриншот до клика обязателен; ветвление длинных чатов (branch)
— штатный приём против раздувания контекста; «доложу» без живой вахты —
обещание, а не механика: отчёт о будущем действии легален только при
взведённом процессе.

# `_inbox` — сюда владелец кладёт файлы, не думая куда

**Правило простое: не знаешь, в какую папку и под каким именем — клади сюда.**
Разгребает наблюдатель (Linux-тело): читает, проверяет, переименовывает по конвенции
и раскладывает по местам. Пустая папка — нормальное состояние.

## Что здесь бывает

Вердикты судей, ответы Мифоса, скачанные PDF, зип-архивы со скриптами, карты SVG,
экспорты чатов — всё, что приходит извне и должно попасть в репозиторий.

## Куда это уезжает

| что пришло | куда кладётся | конвенция имени |
|---|---|---|
| вердикт Прошки | `docs/routeB_bus/proshka/` | `PROSHKA_VERDICT_<ТЕМА>_<YYYY-MM-DD>.md` |
| запрос к Прошке | `docs/routeB_bus/` | `PROSHKA_REQUEST_<ТЕМА>_<YYYY-MM-DD>.md` |
| ответ Мифоса | `docs/<ТЕМА>_<DD_MM_YYYY>/docs/Mythos/` | как прислан, либо `mythos_round_<n>.md` |
| карта / зум SVG | `<папка темы>/maps/` | без ` (1)`, без пробелов в конце |
| публикация PDF | `docs/routeB_bus/litreview/pdfs/` | `<автор>_<тема>_<год>.pdf`, плюс bib+Zotero через `./paper.sh <id> --pdf <файл>` |
| скрипт от агента | `docs/routeB_bus/phase<N>_scripts/` | как назвал автор; авторство — в docstring |
| зип | распаковать, разложить по строкам выше, сам зип **не хранить** |

## Что наблюдатель обязан сделать с каждым файлом

1. **Прочитать**, а не переложить вслепую. Файл, попавший в репозиторий непрочитанным, —
   это то же самое, что его отсутствие.
2. **Проверить утверждения диском**, если файл их содержит: числа сверить со своими,
   ссылки на файлы — грепом.
3. **Сверить дубликаты по `md5`** до удаления чего бы то ни было.
4. **Записать в журнал**, если файл меняет картину: `docs/Progress_Log.md` — развилку,
   `docs/CHAT_DIGESTS.md` — откуда взялась идея, `docs/GENEALOGY.md` — если сдвинулась линия.
5. Для публикаций — закрыть долг: карточка разбора и `NEEDS_CARDS` → `HAVE` в
   `litreview/REFERENCES.md`.

## Чего делать нельзя

`git add -A docs/` вслепую. Так 10 августа в коммит `02d4bc43` уехали `files.zip` и вердикт
Прошки, которых никто ещё не читал. Добавлять файлы **поимённо**.

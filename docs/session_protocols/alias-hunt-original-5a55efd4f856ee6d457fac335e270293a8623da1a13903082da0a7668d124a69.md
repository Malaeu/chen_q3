# alias-hunt — поиск доказанного под чужими именами

## Зачем

Стена в проекте почти всегда уже стоит у кого-то в другой области под другим словом.
06.09: две из трёх «наших» новинок были в печати. 11.09: SL23 оказался Csordas–Varga 1988,
наше ядро оказалось «associated admissible kernel» Csordas 2015 с обрезанием, а ветка
тотальной положительности была уже убита препринтом Михаловского за семь месяцев до нас.
Скилл не ищет статьи по ключевым словам: он переводит объект на несколько словарей и
проверяет каждое попадание числом или цитатой до того, как оно попадёт в отчёт.

## Шаг 0 — объект прежде поиска (5 минут, без агентов)

Файл `BRIEF.md` в scratchpad. Без него поиск не запускается.

1. Формула объекта в наших обозначениях, с нормировкой, из первоисточника (вердикт, лемма),
   с локатором. Не пересказ по памяти.
2. Что уже доказано о нём (список фактов с номерами формул).
3. Отрицательные контроли: явный объект вне класса, на котором наивный механизм умирает.
   Это самый сильный фильтр: кандидат, чей аргумент проходит на контроле, не наш.
4. Одно-два собственных переписывания объекта (помечены «не проверено»), как поисковые подсказки.
5. `./ask.sh <термин>` по 3–5 нашим именам объекта до любого внешнего поиска. Полка первая.

## Шаг 1 — словари (перевод объекта, не синонимы слова)

Минимум три потока, каждый со своим списком имён. Готовые потоки для этого проекта:

| Поток | Имена |
|---|---|
| A операторный | Gram of translates, cross-Gram A B* + B A*, Hankel / Toeplitz / Wiener–Hopf positivity, Sonin space, de Branges, Krein strings, screw function, moment problems, conditionally positive definite |
| B спецфункции | total positivity, Pólya frequency PF_k, Laguerre–Pólya, Turán / Laguerre inequalities, Jensen polynomials, admissible kernels (Csordas), theta log-concavity, Jacobi ODE for θ₃ |
| C физика / вероятность | reflection positivity (Osterwalder–Schrader), Hilbert–Pólya realizations, Bernstein / completely monotone, Biane–Pitman–Yor theta laws, moving-average covariance, frames of translates |

Новый объект получает новые потоки. Правило: поток называет имена объекта, а не темы;
«Riemann hypothesis» как запрос запрещён, он возвращает тысячи страниц ни о чём.

## Шаг 2 — параллельные агенты (один запуск, три агента)

`Agent` × N, `general-purpose`, read-only, каждому: путь к `BRIEF.md`, свой поток, схема ответа.
Инструменты агента: WebSearch, WebFetch (arXiv abs + html/pdf), Scholar Gateway, Consensus, scite.

Схема ответа, строгая; кандидат без любого поля выбрасывается:
1. title / authors / year / venue / arXiv или DOI / URL, который реально скачан;
2. дословная цитата ≤ 3 предложений с локатором (раздел, теорема, страница);
3. их имя нашего объекта;
4. отображение: их g ↔ наш f, их вес ↔ наш вес, их вывод ↔ какой наш пункт;
5. что даёт / чего НЕ даёт (ожидаемый честный ответ: «SL20 не даёт»);
6. уверенность 0–1 и самая дешёвая проверка.

Запрет: имя статьи из памяти без скачанного URL. Репозиторий агент не трогает.
Стоимость ориентир: 3 агента × ~120k токенов × ~6 минут.

## Шаг 3 — проверка оркестратором (обязательна, без неё отчёта нет)

Для каждого кандидата с уверенностью ≥ 0.3 хотя бы одна из проверок своими руками:
- цитата найдена в локальном PDF (`./paper.sh <id>`, `pdftotext`, `grep`), с номером строки;
- число из статьи пересчитано (arb / mpmath, ≥ 30 знаков);
- заявленная подстановка / тождество проверены символьно или на 3 точках.

Противоречащие препринты (два свежих arXiv с разными знаками) решаются числом, не чтением.
Правило 13 проекта: решающее число руками раньше агента.

## Шаг 4 — запись в тот же оборот

- `./paper.sh <id>` для каждой статьи, вошедшей в отчёт; карточка `*_USAGE_CARDS.md`
  (дословно · что даёт нам · чего не даёт · соответствие переменных · что не прочитано);
  `REFERENCES.md` → HAVE.
- Один абзац в `docs/CHAT_DIGESTS.md`: объект, найденные имена, убитые ветки с числом,
  строка CLOSES / OPENS.
- Полный refresh индекса только `spine.py --refresh --reason semantic-index-refresh`
  (`refresh_q3_docs.py` квитанцию не пишет). Один раз, после всех записей.

## Шаг 5 — отчёт владельцу

Таблица кандидатов (имя · их название объекта · даёт / не даёт · проверено чем), убитые ветки,
затем мой выбор следующего хода с ЕСЛИ_A / ЕСЛИ_B и кандидат с вероятностью (правило 19).
Пустой отчёт («ничего не нашли») недопустим без списка словарей и запросов, которые ничего не дали.

## Чего скилл не делает

Не пишет батч Прошке, не меняет TOOLS.yaml, не коммитит. Не заменяет `./ask.sh`: полка спрашивается
до него и после него. Не судит новизну: «наше» только после прохода с моей проверкой локаторов
(память `novelty-pass-before-headline`).

# Progress Log

## 2026-02-21

### Текущая проблема
- Lean/Lake сборка падает каскадом ошибок вида `object file ... .olean of module X does not exist` в цепочке импортов `Main → ... → BrangeHeatCert_..._Checker → PrimePowAutoGT10000/PrimeGrid`.
- Диагноз: **не одна лемма**, а **архитектура импорт-графа** после глубокого разбиения PrimeCert (линейный конвейер autogenerated chunk’ов). При первой неудаче компиляции `.olean` не появляется, и дальше всё рушится «по домино».

### Предложенная стратегия (в 1-й приоритет)
1. **Сделать chunks независимыми**: каждый `PartXXXX.lean` импортирует только `PrimeCert.Core`/`Types`, и НЕ импортирует предыдущий part.
2. **Схлопнуть глубину в 2–4 слоя** через шард-агрегаторы:
   - `Parts` (N файлов)
   - `Shards` (примерно N/200 файлов, каждый импортирует ~200 parts)
   - `Final aggregator` (1 файл импортирует shards)
   - `Export/API boundary` (1 файл, который импортирует checker и экспортирует только нужные теоремы наружу)
3. **Отрезать остальной проект от данных**: `BrangeHeatCert_*` и выше импортируют только `PrimeCert.Exports`, а не внутренние данные.

### Артефакты/скрипты
- `lean_import_graph.py` — быстрый анализатор импорт-графа Lean (ищет длинные цепочки и линейные сегменты).
- `mk_sharded_imports.py` — генератор шард-модулей + финального агрегатора, чтобы резко уменьшить глубину импортов.

### Следующий шаг

  - максимальную глубину,

- После перестройки графа вернуть сборку к реальным Lean-ошибкам и подключить парсер ошибок/семантические `sorry` (если нужно).

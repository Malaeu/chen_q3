# SUPPLIER_CONTRACT.md — контракт поставщика Lean-источников

**Кто обязан читать:** каждое тело, которое пишет Lean в этот репозиторий —
Прошка, Codex, Linux-тело, Mac-тело, любое будущее. Файл один, правила одни.
Прошкин протокол ссылается сюда из W10; для Codex ссылка идёт через его цепь
(`AGENTS.md` → `docs/CODEX_CONTROL.md`), не через этот файл напрямую.

**Чего здесь нет:** судейской дисциплины Прошки (K1–K8), исполнительской
политики Codex, порядка старта сессий. Здесь только то, что одинаково для
всех, кто кладёт Lean-источник.

Появился 2026-08-19. Причина: за сутки шесть узлов прошли ядро, при этом два
зелёных узла подряд УВЕЛИЧИЛИ список открытых входов с четырёх до шести, а
мост был построен вокруг теоремы, доказанной девятью днями раньше, потому что
каталог стыковок никто не спросил.

---

## 1. Узел обязан закрывать больше, чем открывает

Каждый источник несёт в машиночитаемой шапке своей записи две строки:

```
CLOSES: <входы, которые узел закрывает окончательно — именами каталога>
OPENS:  <новые входы, которые узел создаёт — именами каталога>
```

`OPENS` непуст при пустом `CLOSES` → источник не пишется. Вместо него пишется
проза: что упёрлось и что делать — включая убийство маршрута, если это честный
исход. Мост, конструктор и переформулировка сами по себе фронт не двигают.

## 2. Спроси каталог до того, как назвать вход

Один вход: `./ask.sh <термин>` из корня репозитория, секция «СТЫКОВКИ».
Под ней таблица `capability` (теорема / requires / provides, 1100+ записей),
шаги `assembly` и контрпримеры с их зоной охраны.

До объявления нового входа — проверить, нет ли уже поставщика.
До придумывания нового имени — проверить, не знает ли каталог эту вещь под
другим именем. Каталог, расколотый синонимами, не отвечает ничего.

## 3. Имена внешних лемм не берутся из памяти

Каждая лемма Mathlib, объявленная несущей («theorem engine»), приводится с
полным именем И файлом со строкой. Проверка — `rg` по исходникам Mathlib
(`<repo>/q3.lean.aristotle/.lake/packages/mathlib/`), не полка проекта: полка
внешние имена не знает. Прецедент 2026-08-19: `Matrix.PosSemidef.fromBlocks₂₂`
не существует — лемма живёт в `namespace PosDef`, одним namespace левее, с
ровно той сигнатурой, что предполагалась.

Лемма, названная по памяти без проверки, помечается
`UNVERIFIED_EXTERNAL_NAME` в записи источника.

## 4. Запись против вердикта

`SOURCE RECORD` едет с источником в одном коммите и несёт максимум
`SOURCE_WRITTEN`. Суждение proved/refuted пишется отдельным артефактом после
возврата гейта. `sorryAx` в профиле аксиом любой напечатанной теоремы означает
«не доказано», как бы полно ни выглядел исходник. Профиль читается у **каждой**
`#print axioms`-теоремы, не только у заголовочной: 2026-08-19 три теоремы
конструкции были чистыми, а `sorryAx` нёс только plant — защита отсутствовала
при зелёном заголовке.

## 5. Гейт

```
WORKDIR q3.lean.aristotle:
  lake env lean Q3/Proofs/RouteB/<file>.lean
  lake build Q3.Proofs.RouteB.<Module>
WORKDIR корень репозитория:
  scripts/q3_check.sh Q3/Proofs/RouteB/<file>.lean
```

Ожидаемый профиль — `[propext, Classical.choice, Quot.sound]` на каждую
теорему, любое отклонение — находка. Код возврата берётся честно
(`${PIPESTATUS[0]}`, не код `tail`). Гейт гоняет тело с toolchain; написать
файл — не проверить его.

## 6. Квитанции

Каждый положенный Lean-файл сопровождается git-blob и sha256. Совпадение
квитанций подтверждает доставку, но не ядро: три узла подряд имели точные
квитанции и не компилировались.

## 7. YAML-шапка — это и есть handoff

Каждый ответ поставщика начинается с одного машиночитаемого YAML-блока.
Правило разделения: **YAML пишется для исполнителя гейта, проза под ним — для
владельца.** Владелец передаёт исполнителю только YAML; если исполнителю
не хватает данных из шапки, это дефект шапки, а не повод читать прозу.

Обязательные поля шапки:

```
COMMIT | BASE_HEAD        sha коммита в rh_clean; при недоступном write —
                          BASE_HEAD + MBOX_SHA256 вместо него
LEAN_PATH + LEAN_GIT_BLOB + SHA256     на каждый положенный .lean
SOURCE_RECORD_PATH + blob              запись, едущая с источником
PUBLIC_SURFACE                         все печатаемые теоремы поимённо
EXPECTED_AXIOM_PROFILES                на КАЖДУЮ печатаемую теорему
CLOSES / OPENS                         леджер W9, именами каталога
VERIFICATION_HANDOFF                   gate-команды с WORKDIR на каждую
NEXT_LOAD_BEARING_GAP                  следующая стена одним именем
```

YAML — указатель и квитанции, не груз: сам Lean-текст едет через репозиторий
(прямая запись) либо, при отвалившихся write-функциях, отдельным mbox рядом с
шапкой. Шапка без доехавшего груза даёт статус
`COMMIT_READY`, не `SOURCE_WRITTEN`.

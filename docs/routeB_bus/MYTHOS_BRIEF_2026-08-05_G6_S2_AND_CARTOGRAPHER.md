## A.3 Наш рабочий набросок декомпозиции (гипотеза, спорь с ней)

Разрыв: S2 требует опознать `D.limit` как `c · centeredXi · gamma` с ненулевым c и
zero-free gauge. Мюнц даёт `Gwin = ζ·Mellin − хвосты`. Мы видим четыре подзадачи разного веса:

**S2-L1 — FAMILY CROSSWALK** (бухгалтерия, но контракт нужен): показать, что члены
`selectedFamily C k` совпадают с `Gwin h_k Λ_k` после координатной замены `s ↔ z`
(в наших координатах `s = 1/2 + I·z` для Ξ; у Мюнца аргумент сдвинут на `+1/2`).
Нужно зафиксировать: какое именно семейство `h_k` из v3-класса, какая последовательность `Λ_k`.

**S2-L2 — ZERO-FREE GAUGE** (маленькая, самодостаточная, Аристотель-размерная):
перевод ζ → Ξ. Множитель, связывающий их — комбинация `π^{-s/2}·Γ(s/2)` и `s(s−1)/2`.
Утверждение: этот множитель не обращается в ноль на `centeredCriticalStrip`.
В Mathlib есть `Complex.Gamma_ne_zero`; полюса Γ сидят в 0, −2, −4, … — вне полосы.
Выглядит как отдельная лемма на 20–40 строк без внешних зависимостей.

**S2-L3 — TAIL CONTROL** (тяжёлая, настоящая аналитика): `Rminus`/`Rplus` → 0
локально равномерно на полосе вдоль выбранной последовательности. Возможно, часть
количественных оценок переиспользуется из уже доказанных hRm/hRp analyticOnNhd-лемм.

**S2-L4 — NORMALIZATION c ≠ 0** (сильно подешевела): из `SlotAnchor` следует
`family i 0 = centeredXi 0` для всех i, а `centeredXi 0 ≠ 0` теперь ДОКАЗАН.
Значит `D.limit 0 = centeredXi 0 ≠ 0`, и при нормировке gauge `gamma 0 = 1`
константа `c = 1` получается почти механически, без новой аналитики.

**S2-L5 — COFINAL/SAME-FAMILY**: уже закрыт `sameCofinalGuard`, проверить что этого достаточно.

**Claim-vs-fact (заявление против факта):** «строка MAP.md про `centeredXi 0 ≠ 0` говорит 🔓,

уже несёт колонку «Где» с путём и часто с номером строки. Значит: путь → файл существует? →
имя теоремы присутствует? → sorry/axiom? Детерминированно, секунды, ноль токенов, ноль галлюцинаций.

## B.4 Наше встречное предложение (жёстче исходного)

Не детектор дрейфа, а устранение самой возможности дрейфа: статусные значки ✅/🔓/⏳ в §4 MAP.md
перестают писаться руками и начинают ВЫЧИСЛЯТЬСЯ из факта. Человеческие описания
(«что за буква значит человеческим языком») остаются рукописными. Тогда карта не «проверяется
на вранье» — она структурно не может соврать про статус.

Картограф-модель нужен только на ДЕЛЬТУ: появился объект, которого в словаре нет вообще —
придумать ему человеческое имя и строку.

Привязка к уже ратифицированной архитектуре:
- триггер — граница фазы, та же, что Прошка канонизировала вторым вердиктом
  (batch-per-PHASE, 6-полевой `phase_key`); новый триггер не заводим;
- дом — `spine.py`, новая функция рядом с `_staleness_warnings()`; не новый файл, не новый агент;
- anti-orphan декларация: `trigger_owner` = phase-close, `existing_gate` = Proshka phase boundary,
  `spine_section` = SPINE_VIEW — все три поля заполняются;
- в плане это уточнение **P4** (one SPINE_VIEW carries everything) плюс кусок **P1b**
  (stale pointers), порядок P1a→P9 не ломается.

Честное ограничение: машина различает `есть и sorry-free` / `есть с дырами` / `нет файла`,
но НЕ различает «доказано» и «доказано условно на гипотезах» — а у нас пол-крыши именно такая
(`selectedFamily_realZeros` ✅, но conditional на H1+H2a+h510). Поэтому первый заход —
advisory-с-флагом, НЕ блокирующий фазу.

## Режим: микроскоп, не генератор аксиом

**Разрешено:**

```
разрезаем стену
  → строим условную оболочку (shell) на одной точно названной гипотезе
  → Aristotle показывает точный недостающий supplier
  → доказываем supplier отдельным прогоном
  → убираем гипотезу из оболочки
  → запускаем планты
```

**Запрещено:**

```
придумали удобную аксиому
  → отдали Aristotle
  → получили условную теорему
  → объявили движение
```

Разница не в словах. Во втором случае можно собрать идеально компилирующуюся
лестницу, нижняя ступень которой и есть исходная стена — просто под другим
именем. Компиляция это не ловит: Lean проверяет, что из гипотез следует
вывод, а не что гипотезы легче цели.

Пример плохого supplier: `(hM : AnalyticOnNhd ℂ (Mellin h) H)`, когда
следующая задача называется «доказать, что Mellin аналитичен». Это не
открытие, а переименование цели.

## Карточка кандидата в supplier

Aristotle **может предложить** кандидата, но не может повысить его до
допущения проекта. Каждый кандидат приходит с заполненными полями:

```
SUPPLIER:
WHY_SUFFICIENT:
WHY_STRICTLY_WEAKER_THAN_TARGET:
DEPENDENCIES:
NONCIRCULARITY:
COUNTEREXAMPLE_IF_DROPPED:
NEXT_DISCHARGE_THEOREM:
```

**Пустое `WHY_STRICTLY_WEAKER_THAN_TARGET` → кандидат в карантин.** Это
единственное поле, отличающее находку от переименования.

## Четыре режима прогона

| Режим | Отвечает на вопрос | Когда |
|---|---|---|
| **Shell** | если supplier X существует, остальная архитектура собирается? | первым, один раз на фронт |
| **Supplier** | доказать ровно одну недостающую теорему | после shell, по одной |
| **Ablation** | какие гипотезы реально нужны, а какие взяты про запас | после supplier |
| **Plant** | ловушки и мутанты — проверка доверия к конструкции | отдельным проектом |

**После shell полный пакет повторно не отправляется.** Уходит только один
theorem.

Планты не смешивать с ядром: один прогон, который одновременно доказывает
теорему, строит явные bump-функции, выводит знак производной и убивает двух
мутантов, тратит поисковый бюджет на независимые фронты.

## Ограничение глубины

```
один прогон  = одна теорема
одна теорема = один семантический интерфейс
один интерфейс = один компиляционный гейт
```

Два подряд `NO_PROGRESS` → смена представления, а не третья попытка.

**Шестичасовой глубокий прогон допустим только при одновременном выполнении
всех пяти условий:**

1. точный объект source-locked;
2. теорема несущая (load-bearing), а не удобная;
3. бумажный маршрут доказательства уже есть;
4. дешёвый поиск по Mathlib и существующему API исчерпан;
5. **даже провал вернёт названную лемму поменьше**.

Иначе шесть часов уходят на поиск, который не уменьшает разрыв. «Пять из
шести» — не 83% прогресса: незакрытая шестая лемма может быть всей задачей.

## Обязательный аудит перед доверием результату

Собравшийся Lean ≠ доказанная нужная теорема.

- **`RESULT.md` вердиктом не является.** На многораундовых проектах он
  отстаёт: `RESULT.md` от R5 продержался в архиве R6 и говорил `GAP` там, где
  дырка была уже закрыта. Судить только по Lean-исходникам.
- **Знаки и формы сверять побайтово против контракта.** Одно успешно
  собравшееся утверждение с неверным знаком — доказательство не той теоремы.
- `#print axioms` для всех экспортируемых деклараций; ожидание — ровно
  `propext, Classical.choice, Quot.sound`.
- taint-scan: `sorry | admit | axiom | native_decide | exact?`.

## Текущее применение (2026-07-30)

Фронт Мюнца сжат до одного поставщика:

```
MellinDifferentiableOnRightHalfPlane_Icc0_IcoLipschitz
```

Оболочка уже собрана условно: `T4a ⟹ pole-subtracted T4c–T4g ⟹ T5`.
Передоказывать не нужно ничего из: dslope-тождеств, removable-расширения
residue-фактора, аналитичности произведения, склейки теоремой единственности,
punctured/pole-value следствий.

**Гейт перед следующим прогоном:** харвест свежего исходника и семантический
диф — проверить, что в `T5` стоит `- Rminus - Rplus`, а не `- Rminus + Rplus`.
В историческом R6-файле знак расходился. Пока не сверено побайтово, условный
`T5` импортировать нельзя.

Зарегистрированный прогноз судьи:

```
P-ARISTOTLE-T4A:
  T4a закроется через существующий mellin_differentiableAt_of_isBigO_rpow;
  главное трение будет в local integrability / обработке endpoint a.e.,
  а не в голоморфном исчислении с параметром.
```

Запрещённый ход: усиливать `LipschitzOnWith` до глобального `LipschitzWith`
ради удобной готовой леммы — целевая `h` может иметь скачок в endpoint `b`,
контракт v3 такой shortcut прямо запрещает.

`⟨v, Q_arch v⟩` с эталоном `route2_arch = 0.047697482652328006439872417749`

Время на точку `ψ_arch` — около 67 с.

### Что известно про этот незавершённый счёт (R5 журнала)

`ψ_arch` выходит **почти постоянной**, `≈ ¼ + δ` с `δ ~ 10⁻³`. Разделённая разность убивает
аддитивную константу, поэтому внедиагональный блок законно живёт в четвёртом знаке — но
относительная точность самого `δ` при `rem_bound ~ 10⁻⁷` составляет лишь `~10⁻⁴`, и для
сверки с двадцатизначным эталоном этого мало.

**Единственное непроверенное звено:** они строят квадратичную форму напрямую через
тест-функцию `v → T_v → K_v → g(r)` с множителем `1/π`; здесь она собирается через матрицу
и разделённые разности с `1/π²`. Пути обязаны совпасть, но мост между ними **не выведен**.

### Что делать дальше

1. **Диагональ — на аналитику.** Сейчас конечная разность с шагом `10⁻¹²` от тройной
   квадратуры: вычитание близких чисел, делённое на `10⁻¹²`. `∂S/∂x` берётся под интегралом
   в замкнутой форме (`A = 2πx` и `B = 2πx/L` линейны по `x`) — как уже сделано для ветки
   `x = 0`.
2. **Сузить `rem_bound`** — больше периодов в остатке (`NPER`), дальше точка сшивки (`T0`).
3. **Если сумма разойдётся на порядок** — вывести мост между их путём через тест-функцию и
   путём через матрицу, прежде чем чинить точность. Ошибка тогда в схеме, а не в счёте.

### Осторожно

`x = 0` даёт ровно ноль (`B = 0 ⇒ S ≡ 0`), поэтому первая строка и первый столбец матрицы
идут **другой веткой кода**. Место, где ошибка спрячется незаметно.

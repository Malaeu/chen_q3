# specs_docs — карта входов и триггеров

Здесь лежат спеки о том, **как устроен репозиторий**, а не о том, как считать математику.
Заводится, чтобы не реконструировать порядок чтения и цепочки записи заново каждую сессию.

| Файл | Что внутри |
|---|---|
| `ENTRY_SPEC.md` | что читается при старте сессии, в каком порядке, чем каждый файл пишется и что из этого мертво |
| `TOOLS_SPEC.md` | **точка входа по инструментам.** Часть I — спеки (что делает, что пишет, что мертво). Часть II — операционный каталог: шпаргалка команд, когда читать, когда писать. Кернел ссылается сюда одной строкой |
| `CONDITIONAL_CONTOURS.md` | условные контуры (embeddings, oracle, insights, aristotle, cognitive): что делали, чем заменены, что превращать в skill |
| `CONTOURS_CONSOLIDATION.md` | все найденные контуры: функция, синергия, замещаемость, вердикт — что ядро, что слить, что заморозить; ~16 узлов → 7 |
| `entry_audit.sh` | read-only прогон: свежие даты и активность по всем файлам порядка чтения |

Границы:

- это **навигация, не политика** — поведение исполнителя задаёт `docs/CODEX_CONTROL.md`;
- ничего отсюда не переопределяет канонический кернел;
- даты в спеках получены из `git log`, а не из шапок документов: документ может
  объявлять себя `ACTIVE` и не меняться полгода, такие случаи здесь и ловятся.

## Artifact hashes

The manifest records SHA256 hashes of each midpoint/radius CSV so downstream
checks can detect silent artifact drift.

This matters because Step 20 showed that the midpoint contract is part of the
certificate, not just the radii.  A radius around the wrong midpoint is not a
valid certificate object.

## Search synthesis

Local search found the relevant existing anchors:

- the `PSD-pd` fallback finite-certificate lane;
- the `Q_zeta` core rule that finite interval certificates are legitimate
  backend progress;
- the existing PrimeCert closure pattern: explicit certificate artifacts should
  be generated, checked, and then consumed by a small theorem receiver.

External sanity search only confirms the engineering pattern: certificate-based
verified numerical workflows separate untrusted computation artifacts from a
small checker/receiver.  No external theorem is imported here.

## Theorem role

The manifest does not prove RH.

It supplies the concrete finite-family object needed by Step 23:

\[
\text{FiniteCert}(\alpha)
\]

for each manifest row with `status=pass`.

The next bridge is:

\[
\text{manifest family}
\Rightarrow
\text{directed certificate family}
\Rightarrow
\text{boundary-null exhaustion}
\Rightarrow
\text{PSD-pd}.
\]

## Next move

The fastest next step is to introduce a lightweight manifest consumer:

1. read the manifest;
2. select rows with `status=pass`;
3. expose them as `FiniteCert` records for the proof ledger;
4. keep the family/exhaustion theorem separate from individual block checking.

This keeps the finite proof-grade blocks auditable without pretending that one
block already proves the global theorem.

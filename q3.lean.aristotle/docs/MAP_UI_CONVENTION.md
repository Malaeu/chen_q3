# MAP UI CONVENTION — интерактивные карты проекта (зум-компилятор)

Дата: 2026-07-11 · Владелец: Mythos · Класс: living doc, конвенция для ВСЕХ агентов, рисующих карты проекта (сессии Mythos, Codex-сторона, любые будущие инструменты).
Подчинение: статусы узлов берутся ТОЛЬКО из леджеров на диске (MASTER_GOAL §5, ROUTE_B_THEOREM_CONTRACT_v2 §7, ROUTE_B_STATE.md History). Карта — проекция леджера, не источник правды.

---

## 1. Механика

- Карта = SVG, отрисованный инструментом-визуализатором прямо в чат.
- Каждый узел = группа `<g class="node c-...">` с обработчиком `onclick="sendPrompt('…')"`. Среда чата предоставляет функцию `sendPrompt(text)`, отправляющую текст как сообщение пользователя.
- Клик = новый исследовательский ход: агент обязан РЕАЛЬНО проработать узел (перо, аудит, доказательство) и только затем нарисовать дочернюю карту. Заготовленного дерева нет; глубина зума не ограничена.
- Текст каждого onclick — самодостаточный вопрос: агент в свежей сессии обязан понять его без контекста карты.

## 2. Палитра (конвенция Ылши; закреплена в памяти)

| Цвет | Класс | Семантика |
|---|---|---|
| зелёный | `c-teal` | доказано / закрыто в леджере |
| красный | `c-coral` | НЕ доказано / открыто — кликабельная цель работы |
| серый | `c-gray` | справка / навигация / заморожено / входы |

- Фиолетовый (`c-purple`) ЗАПРЕЩЁН.
- Защита от цветовых сбоев: статус ОБЯЗАН дублироваться словом первой позицией подписи узла.
- Легенда внизу каждой карты обязательна (1–2 строки `class="ts"`).

## 3. Слова-статусы (первая позиция подписи, за словом — «·»)

`доказано ·` (только зелёный) · `открыто ·` (красный) · `частично ·` (красный! четвёртый цвет не вводить; пример: «частично · доказано в сессии, не заморожено пером») · `справка ·` / `заморожено ·` (серый).

Правило зелёного: зелёным становится только то, что закрыто В ЛЕДЖЕРЕ (перо заморожено / гейт PASS / теорема с проверкой). Доказанное в чате, но не замороженное — красное с тегом «частично».

## 4. Возврат и хлебные крошки

- На каждой карте ниже верхнего уровня ПЕРВЫЙ блок (сверху-слева, серый): `⟵ Зум-аут: <родитель>`; onclick — sendPrompt карты родителя; в подписи или внизу карты — крошка пути: `путь: L0 → D0 → D0.3`.
- Верхний уровень вместо возврата несёт справочный блок «Навигация».
- Голосовые команды работают всегда: «зум аут» = уровень выше; «зумни X» = уровень ниже; агент знает текущий уровень из контекста и крошки.

## 5. Стандартные промпт-имена (совместимость карт между агентами)

- `зум аут` — карта уровнем выше.
- `Зумни <номер/имя узла>` — под-карта узла (совместимо с замороженной нумерацией 1–5).
- `Лист <ID>: <название> — разложи на под-листья с судьями и стоп-кодами` — стандартный зум листа Лэмпорт-дерева.
- `Покажи <объект> шаг за шагом` — проваливание в ДОКАЗАННЫЙ (зелёный) узел: показ тела доказательства.
- Действия: `пиши <артефакт>` · `заморозь <перо>` · `патчи` · `го` (шина).

## 6. Технические правила

- viewBox шириной 680; safe-зона x ∈ [40, 640].
- ≤ 9–10 блоков на карту; больше — дели уровень.
- Заголовок узла ≤ ~30 символов, подпись ≤ ~45; без эмодзи.
- Дочерние узлы одного родителя — единый стиль формулировок.
- Стрелки — только там, где есть логическая зависимость; сетка без стрелок допустима для перечней листьев.

## 7. Шаблон узла (скелет для воспроизведения на любой стороне)

```svg
<g class="node c-coral" onclick="sendPrompt('Лист D0.6: нормировки s, b, c — разложи на под-листья с судьями и стоп-кодами')">
  <rect x="350" y="280" width="290" height="56" rx="8" stroke-width="0.5"/>
  <text class="th" x="495" y="300" text-anchor="middle" dominant-baseline="central">D0.6: нормировки s, b, c</text>
  <text class="ts" x="495" y="320" text-anchor="middle" dominant-baseline="central">открыто · b_λ всё ещё без формулы</text>
</g>
```

## 8. Приёмка карты (чек-лист ревью)

1. Палитра только зелёный/красный/серый; фиолетового нет.
2. Каждый узел несёт слово-статус первой позицией подписи.
3. Легенда присутствует.
4. Ниже верхнего уровня есть «⟵ Зум-аут» + крошка пути.
5. Каждый onclick — самодостаточный вопрос.
6. Статусы совпадают с леджером на диске; расхождение = `MAP_LEDGER_MISMATCH`, карта отклоняется.

Подсадка ревью (K1): карта с нарочно неверным статусом одного узла обязана быть отклонена по пункту 6 — ревьюер, пропустивший подсадку, недействителен.

**Феномен**

**Что это на самом деле**  
Это **implicit basis selection** — модель ищет **наименьшее описание** задачи.

**Что измерять (обязательно):**

- **Entropy(slot usage)** — степень сжатия
- **Mutual Information(slotᵢ ; target)** — *зачем* слот нужен

👉 Это прямой аналог:
- выбора **доминирующих мод** в операторе
- выбора **низкорангового приближения**

## 3. Co-adaptation — это не «договорились», это **локальный резонанс**

**Феномен**  
Слоты + основная сеть подгоняются слишком плотно → плохо переносится.

**Реальная интерпретация**  
Модель нашла **узкую конфигурацию**, которая:
- минимизирует loss
- **не является универсальной**

Это ровно то, что в математике выглядит как:
- резонанс
- негрубая точка

- **Gradient correlation** между слотами
- **Fisher overlap**
- **Rollout divergence** (train vs transfer)

      450 +def measure_slot_effect_norm(model, data, device, n_eval=100):                                                                                         
      451 +    """                                                                                                                                                
      452 +    Measure how much each slot ACTUALLY affects the hidden state.                                                                                      
      453 +                                                                                                                                                       
      454 +    For each slot, compare hidden state WITH vs WITHOUT that slot.                                                                                     
      455 +    L2 norm of difference = how much that slot matters for representations.                                                                            
      456 +                                                                                                                                                       
      457 +    This is different from attention mass: a slot can receive attention                                                                                
      458 +    but have negligible effect if its values are small.                                                                                                
      459 +    """                                                                                                                                                
      460 +    model.eval()                                                                                                                                       
      461 +                                                                                                                                                       
      462 +    n_slots = model.n_memory_slots                                                                                                                     
      463 +    slot_effects = []                                                                                                                                  
      464 +                                                                                                                                                       
      465 +    idx = torch.randint(0, len(data), (n_eval,))                                                                                                       
      466 +    batch = data[idx].to(device)                                                                                                                       
      467 +    x = batch[:, :-1]                                                                                                                                  
      468 +                                                                                                                                                       
      469 +    # Get baseline hidden states (all slots active)                                                                                                    
      470 +    with torch.no_grad():                                                                                                                              
      471 +        # We need to modify forward to return hidden states                                                                                            
      472 +        # For now, use a proxy: measure output change                                                                                                  
      473 +        pi_base, mu_base, sigma_base, *_ = model(x)                                                                                                    
      474 +        pred_base = (pi_base * mu_base).sum(dim=-1)  # (B, T)                                                                                          
      475 +                                                                                                                                                       
      476 +    original_memory = model.memory_bank.memory.data.clone()                                                                                            
      477 +                                                                                                                                                       
      478 +    for slot_idx in range(n_slots):                                                                                                                    
      479 +        # Zero out this slot                                                                                                                           
      480 +        model.memory_bank.memory.data[slot_idx] = 0                                                                                                    
      481 +                                                                                                                                                       
      482 +        with torch.no_grad():                                                                                                                          
      483 +            pi, mu, sigma, *_ = model(x)                                                                                                               
      484 +            pred = (pi * mu).sum(dim=-1)                                                                                                               
      485 +                                                                                                                                                       
      486 +        # L2 distance in prediction space                                                                                                              
      487 +        effect = (pred_base - pred).pow(2).mean().sqrt().item()                                                                                        
      488 +        slot_effects.append(effect)                                                                                                                    
      489 +                                                                                                                                                       
      490 +        # Restore                                                                                                                                      
      491 +        model.memory_bank.memory.data = original_memory.clone()                                                                                        
      492 +                                                                                                                                                       
      493 +    # Normalize to percentages                                                                                                                         
      494 +    total_effect = sum(slot_effects) + 1e-10                                                                                                           
      495 +    slot_effect_pct = [e / total_effect for e in slot_effects]                                                                                         
      496 +                                                                                                                                                       
      497 +    return {                                                                                                                                           
      498 +        "slot_effects": slot_effects,                                                                                                                  
      499 +        "slot_effect_pct": slot_effect_pct,                                                                                                            
      500 +        "dominant_slot": np.argmax(slot_effects),                                                                                                      
      501 +        "effect_entropy": -sum(p * np.log(p + 1e-10) for p in slot_effect_pct),                                                                        
      502 +        "max_effect": max(slot_effects),                                                                                                               
      503 +    }                                                                                                                                                  
      504 +                                                                                                                                                       
      505 +

### Что это делает (сигналы → метрики)

- **Shortcut** → **attention entropy**, **top-k mass**, **concentration ratio**
- **Symmetry** → **cosine similarity matrix** между слотами, **mean off-diag**
- **Co-adaptation** → (а) **ablation redistribution** (если есть attn-stats), (б) **gradient correlation**
- **Rollout fragility** → **KL(train_attn || rollout_attn)** + сдвиг по слотам
- **“Что реально важно”** → **slot effect norm** (влияние слота на предсказание), а не просто “на него смотрят”

def seed_all(seed: int = 1337) -> None:
    torch.manual_seed(seed)
    np.random.seed(seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(seed)


def safe_mkdir(p: Path) -> None:
    p.mkdir(parents=True, exist_ok=True)


def to_numpy(x: torch.Tensor) -> np.ndarray:
    return x.detach().float().cpu().numpy()


def entropy(p: np.ndarray, eps: float = 1e-12) -> float:
    p = np.clip(p, eps, 1.0)
    p = p / p.sum()
    return float(-(p * np.log(p)).sum())


def kl_div(p: np.ndarray, q: np.ndarray, eps: float = 1e-12) -> float:
    p = np.clip(p, eps, 1.0)
    q = np.clip(q, eps, 1.0)
    p = p / p.sum()
    q = q / q.sum()
    return float((p * np.log(p / q)).sum())


def cosine_sim_matrix(M: torch.Tensor, eps: float = 1e-12) -> torch.Tensor:
    # M: [S, D]
    M = M.float()
    M = M / (M.norm(dim=-1, keepdim=True) + eps)
    return M @ M.t()


# -----------------------------
# MDN helpers (generic)
# -----------------------------

def mdn_nll(pi: torch.Tensor, mu: torch.Tensor, sigma: torch.Tensor, y: torch.Tensor, eps: float = 1e-8) -> torch.Tensor:
    """
    Generic **MDN NLL** for Gaussian mixture.
    Shapes expected:
      pi:    [B, T, K] (mixture weights, sum=1 on K)
      mu:    [B, T, K]
      sigma: [B, T, K] (positive)
      y:     [B, T]    (target)
    Returns:
      nll: scalar tensor
    """
    # Ensure sigma positive
    sigma = torch.clamp(sigma, min=eps)
    y = y.unsqueeze(-1)  # [B, T, 1]
    log_prob = -0.5 * (((y - mu) / sigma) ** 2 + 2.0 * torch.log(sigma) + math.log(2.0 * math.pi))  # [B,T,K]
    # log sum exp with pi
    log_pi = torch.log(torch.clamp(pi, min=eps))
    log_mix = torch.logsumexp(log_pi + log_prob, dim=-1)  # [B,T]
    nll = -log_mix.mean()
    return nll


def mdn_point_pred(pi: torch.Tensor, mu: torch.Tensor) -> torch.Tensor:
    """
    Simple point prediction: E[y] = sum_k pi_k * mu_k
    """
    return (pi * mu).sum(dim=-1)  # [B,T]

# Memory stats adapter (best-effort)

@dataclass
class MemoryStats:
    """
    **MemoryStats** is an adapter: tries to read attention-to-memory distribution from model.

    We support two cases:
    1) model(x, collect_memory_stats=True) updates model.memory_bank internal counters
       and exposes get_attn_distribution()
    2) otherwise, we try to attach forward hooks (only if memory module exposes attn weights)
       -> in practice, your repo likely already has memory_bank stats in diagnose scripts.
    """
    attn_dist: Optional[np.ndarray] = None
    has_native: bool = False
    notes: str = ""


def try_get_memory_stats(model: torch.nn.Module, x: torch.Tensor) -> MemoryStats:
    stats = MemoryStats()

    mb = getattr(model, "memory_bank", None)
    if mb is None:
        stats.notes = "No model.memory_bank found."
        return stats

    # Case 1: native stats API
    if hasattr(mb, "reset_stats") and hasattr(mb, "get_attn_distribution"):
        stats.has_native = True
        try:
            mb.reset_stats()
            with torch.no_grad():
                # Some repos use flag name collect_memory_stats
                try:
                    _ = model(x, collect_memory_stats=True)
                except TypeError:
                    _ = model(x)
            dist = mb.get_attn_distribution()
            if isinstance(dist, torch.Tensor):
                stats.attn_dist = to_numpy(dist)
            else:
                stats.attn_dist = np.array(dist, dtype=np.float64)
            return stats
        except Exception as e:
            stats.notes = f"Native memory stats failed: {repr(e)}"
            return stats

    stats.notes = "memory_bank found but no reset_stats/get_attn_distribution API."
    return stats


def get_memory_tensor(model: torch.nn.Module) -> Optional[torch.Tensor]:
    """
    Try to locate the learnable memory slots tensor:
    common patterns:
      model.memory_bank.memory
      model.memory_bank.slots
      model.memory_bank.mem
    """
    mb = getattr(model, "memory_bank", None)
    if mb is None:
        return None
    for name in ["memory", "slots", "mem"]:
        if hasattr(mb, name):
            t = getattr(mb, name)
            if isinstance(t, torch.Tensor):
                return t
            # sometimes it's nn.Parameter
            if hasattr(t, "data") and isinstance(t.data, torch.Tensor):
                return t
    return None

# Core metrics

def measure_attention_concentration(attn_dist: np.ndarray) -> Dict[str, Any]:
    """
    **Attention distribution** over slots -> entropy / concentration.
    """
    p = attn_dist.astype(np.float64)
    p = p / (p.sum() + 1e-12)
    ent = entropy(p)
    top1 = float(np.max(p))
    top2 = float(np.sort(p)[-2]) if p.size >= 2 else 0.0
    top2_mass = float(np.sort(p)[-2:].sum()) if p.size >= 2 else float(top1)
    # "shortcut ratio": how much sits in top-2
    return {
        "mem_entropy": ent,
        "top1_mass": top1,
        "top2_mass": top2_mass,
        "concentration_ratio": top2_mass,  # shorthand
        "attn_dist": p,
    }


def measure_slot_similarity(memory_slots: torch.Tensor) -> Dict[str, Any]:
    """
    **Slot similarity** = cosine matrix on slot vectors.
    High off-diagonal => symmetry / redundancy.
    """
    S = memory_slots.shape[0]
    sim = cosine_sim_matrix(memory_slots).detach().cpu().numpy()
    mask = ~np.eye(S, dtype=bool)
    off = sim[mask]
    return {
        "mean_similarity_offdiag": float(off.mean()) if off.size else 1.0,
        "max_similarity_offdiag": float(off.max()) if off.size else 1.0,
        "similarity_matrix": sim,
    }


def ablation_delta_nll(
    model: torch.nn.Module,
    x: torch.Tensor,
    y: torch.Tensor,
    memory_slots: torch.Tensor,
) -> Dict[str, Any]:
    """
    **Ablation**: zero out each slot and measure ΔNLL.
    Needs direct write access to memory slots tensor.
    """
    model.eval()
    with torch.no_grad():
        pi0, mu0, sigma0, *rest = model(x)
        base_nll = float(mdn_nll(pi0, mu0, sigma0, y).item())

    orig = memory_slots.detach().clone()

    deltas: List[float] = []
    for i in range(orig.shape[0]):
        with torch.no_grad():
            memory_slots.data[i].zero_()  # ablate
            pi, mu, sigma, *_ = model(x)
            nll = float(mdn_nll(pi, mu, sigma, y).item())
        deltas.append(nll - base_nll)
        with torch.no_grad():
            memory_slots.data.copy_(orig)

    deltas_np = np.array(deltas, dtype=np.float64)
    return {
        "base_nll": base_nll,
        "delta_nll_per_slot": deltas_np,
        "dominant_slot_by_nll": int(deltas_np.argmax()),
        "max_delta_nll": float(deltas_np.max()),
        "mean_delta_nll": float(deltas_np.mean()),
    }


def gradient_correlation(
    model: torch.nn.Module,
    data: torch.Tensor,
    device: torch.device,
    n_batches: int,
    batch_size: int,
) -> Dict[str, Any]:
    """
    **Gradient correlation** across slots = co-adaptation signal.
    We compute gradients of the memory slots tensor and correlate them.
    """
    memory_slots = get_memory_tensor(model)
    if memory_slots is None:
        return {"ok": False, "reason": "No memory tensor found."}

    model.train()
    S = memory_slots.shape[0]
    grads: List[List[torch.Tensor]] = [[] for _ in range(S)]

    for _ in tqdm(range(n_batches), desc="grad-corr", leave=False):
        idx = torch.randint(0, data.shape[0], (batch_size,), device=device)
        batch = data[idx]
        x = batch[:, :-1]
        y = batch[:, 1:]

        pi, mu, sigma, *_ = model(x)
        loss = mdn_nll(pi, mu, sigma, y)

        model.zero_grad(set_to_none=True)
        loss.backward()

        g = memory_slots.grad
        if g is None:
            return {"ok": False, "reason": "memory_slots.grad is None (no grad flow?)"}
        g = g.detach().float().cpu()
        for i in range(S):
            grads[i].append(g[i].clone())

    slot_grads = [torch.stack(gs, dim=0) for gs in grads]  # [S][B,D]
    grad_norms = np.array([float(g.norm(dim=-1).mean().item()) for g in slot_grads], dtype=np.float64)

    flat = [g.flatten().numpy() for g in slot_grads]
    corr = np.zeros((S, S), dtype=np.float64)
    for i in range(S):
        for j in range(S):
            c = np.corrcoef(flat[i], flat[j])[0, 1]
            if np.isnan(c):
                c = 0.0
            corr[i, j] = c

    mask = ~np.eye(S, dtype=bool)
    off = np.abs(corr[mask])
    return {
        "ok": True,
        "grad_norms": grad_norms,
        "grad_corr_matrix": corr,
        "mean_abs_grad_corr_offdiag": float(off.mean()) if off.size else 0.0,
        "max_abs_grad_corr_offdiag": float(off.max()) if off.size else 0.0,
        "grad_leader": int(grad_norms.argmax()),
    }


def train_vs_rollout_stability(
    model: torch.nn.Module,
    batch: torch.Tensor,
    device: torch.device,
    rollout_steps: int,
    context_len: int,
) -> Dict[str, Any]:
    """
    **Train vs Rollout stability**:
      compute memory attention distribution under teacher forcing vs autoregressive rollout,
      then measure **KL divergence** and per-slot shift.
    Requires memory stats API on model.memory_bank.
    """
    model.eval()
    B, T = batch.shape
    x_tf = batch[:, :-1].to(device)
    stats_tf = try_get_memory_stats(model, x_tf)

    if stats_tf.attn_dist is None:
        return {"ok": False, "reason": f"no memory stats: {stats_tf.notes}"}

    # rollout
    seq = batch[:, :context_len].to(device).clone()
    mb = getattr(model, "memory_bank", None)
    if mb is None or not hasattr(mb, "reset_stats") or not hasattr(mb, "get_attn_distribution"):
        return {"ok": False, "reason": "no memory_bank stats API for rollout"}

    mb.reset_stats()
    with torch.no_grad():
        for _ in range(rollout_steps):
            # Forward on current seq
            try:
                pi, mu, sigma, *_ = model(seq, collect_memory_stats=True)
            except TypeError:
                pi, mu, sigma, *_ = model(seq)

            # Use last timestep point prediction (mean under mixture)
            pi_last = pi[:, -1, :]
            mu_last = mu[:, -1, :]
            pred_next = (pi_last * mu_last).sum(dim=-1)  # [B]
            seq = torch.cat([seq, pred_next.unsqueeze(-1)], dim=-1)

    dist_roll = mb.get_attn_distribution()
    dist_roll = to_numpy(dist_roll)

    p = stats_tf.attn_dist
    q = dist_roll
    p = p / (p.sum() + 1e-12)
    q = q / (q.sum() + 1e-12)

    return {
        "ok": True,
        "train_attn": p,
        "rollout_attn": q,
        "kl_train_to_rollout": kl_div(p, q),
        "abs_shift": np.abs(p - q),
        "max_shift_slot": int(np.abs(p - q).argmax()),
        "max_shift": float(np.abs(p - q).max()),
    }


def slot_effect_norm(
    model: torch.nn.Module,
    x: torch.Tensor,
    memory_slots: torch.Tensor,
) -> Dict[str, Any]:
    """
    **Slot effect norm**:
      how much predictions change if slot is zeroed.
    Uses point pred E[y] for simplicity (stable + cheap).
    """
    model.eval()
    with torch.no_grad():
        pi0, mu0, sigma0, *_ = model(x)
        pred0 = mdn_point_pred(pi0, mu0)  # [B,T]

    orig = memory_slots.detach().clone()
    effects: List[float] = []
    for i in range(orig.shape[0]):
        with torch.no_grad():
            memory_slots.data[i].zero_()
            pi, mu, sigma, *_ = model(x)
            pred = mdn_point_pred(pi, mu)
            eff = (pred0 - pred).pow(2).mean().sqrt().item()
        effects.append(float(eff))
        with torch.no_grad():
            memory_slots.data.copy_(orig)

    eff_np = np.array(effects, dtype=np.float64)
    total = float(eff_np.sum() + 1e-12)
    pct = eff_np / total
    return {
        "effects_l2": eff_np,
        "effects_pct": pct,
        "dominant_slot_by_effect": int(pct.argmax()),
        "effect_entropy": entropy(pct),
        "max_effect_pct": float(pct.max()),
    }

def load_data(path: Path, device: torch.device) -> torch.Tensor:
    """
    Loads .pt tensor with shape [N, T] (sequence of spacings).
    """
    data = torch.load(path, map_location="cpu", weights_only=False)
    if isinstance(data, dict) and "data" in data:
        data = data["data"]
    if not isinstance(data, torch.Tensor):
        raise ValueError(f"Expected torch.Tensor in {path}, got {type(data)}")
    return data.to(device)


def sample_batch(data: torch.Tensor, n: int, device: torch.device) -> torch.Tensor:
    idx = torch.randint(0, data.shape[0], (n,), device=device)
    return data[idx]


def write_jsonl(path: Path, row: Dict[str, Any]) -> None:
    with path.open("a", encoding="utf-8") as f:
        f.write(json.dumps(row, ensure_ascii=False, default=_json_default) + "\n")


def _json_default(o: Any) -> Any:
    if isinstance(o, np.ndarray):
        return o.tolist()
    if isinstance(o, (np.float32, np.float64)):
        return float(o)
    if isinstance(o, (np.int32, np.int64)):
        return int(o)
    return str(o)


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--ckpt", type=str, required=True, help="Path to checkpoint .pt")
    ap.add_argument("--data", type=str, required=True, help="Path to val.pt (tensor [N,T])")
    ap.add_argument("--device", type=str, default="cuda", help="cuda / cpu / mps")
    ap.add_argument("--out-dir", type=str, default="out/diagnostics", help="Output directory")
    ap.add_argument("--n-eval", type=int, default=256, help="Batch size for eval metrics")
    ap.add_argument("--grad-batches", type=int, default=8, help="How many batches for grad correlation")
    ap.add_argument("--grad-batch-size", type=int, default=64, help="Batch size for grad correlation")
    ap.add_argument("--rollout-steps", type=int, default=50, help="Autoregressive rollout steps")
    ap.add_argument("--context-len", type=int, default=128, help="Seed length for rollout")
    ap.add_argument("--seed", type=int, default=1337, help="RNG seed")
    ap.add_argument("--jsonl-name", type=str, default="memory_diagnostics.jsonl", help="JSONL filename")
    args = ap.parse_args()

    device = torch.device(args.device)
    seed_all(args.seed)

    out_dir = Path(args.out_dir)
    safe_mkdir(out_dir)
    jsonl_path = out_dir / args.jsonl_name

    ckpt_path = Path(args.ckpt)
    data_path = Path(args.data)

    print(f"[+] ckpt: {ckpt_path}")
    print(f"[+] data: {data_path}")
    print(f"[+] out:  {out_dir}")

    ckpt = load_ckpt(ckpt_path, device)
    # ---- MODEL ----
    model = build_model_from_ckpt(ckpt, device).to(device)
    model.eval()

    # ---- DATA ----
    data = load_data(data_path, device=device)
    batch = sample_batch(data, args.n_eval, device=device)
    x = batch[:, :-1]
    y = batch[:, 1:]

    # ---- MEMORY TENSOR ----
    mem = get_memory_tensor(model)
    if mem is None:
        raise RuntimeError("Could not find memory slots tensor inside model.memory_bank.")

    S = mem.shape[0]
    print(f"[+] memory slots: {S}  dim: {mem.shape[-1]}")

    # ---- Stats ----
    row: Dict[str, Any] = {
        "ckpt": str(ckpt_path),
        "data": str(data_path),
        "n_eval": args.n_eval,
        "n_slots": S,
    }

    # A) Attention concentration (requires stats API)
    mstats = try_get_memory_stats(model, x)
    if mstats.attn_dist is not None:
        attn = measure_attention_concentration(mstats.attn_dist)
        row.update({f"attn_{k}": v for k, v in attn.items() if k != "attn_dist"})
        row["attn_dist"] = attn["attn_dist"]
    else:
        row["attn_note"] = mstats.notes

    # B) Similarity
    sim = measure_slot_similarity(mem.detach())
    row.update({
        "sim_mean_offdiag": sim["mean_similarity_offdiag"],
        "sim_max_offdiag": sim["max_similarity_offdiag"],
        "sim_matrix": sim["similarity_matrix"],
    })

    # C) Ablation ΔNLL
    abl = ablation_delta_nll(model, x, y, mem)
    row.update({
        "base_nll": abl["base_nll"],
        "delta_nll_per_slot": abl["delta_nll_per_slot"],
        "dominant_slot_by_nll": abl["dominant_slot_by_nll"],
        "max_delta_nll": abl["max_delta_nll"],
        "mean_delta_nll": abl["mean_delta_nll"],
    })

    # D) Gradient correlation
    gcorr = gradient_correlation(
        model=model,
        data=data,
        device=device,
        n_batches=args.grad_batches,
        batch_size=args.grad_batch_size,
    )
    row["gradcorr"] = gcorr

    # E) Train vs Rollout (requires stats API)
    tvr = train_vs_rollout_stability(
        model=model,
        batch=batch,
        device=device,
        rollout_steps=args.rollout_steps,
        context_len=args.context_len,
    )
    row["train_vs_rollout"] = tvr

    # F) Slot effect norm
    eff = slot_effect_norm(model, x, mem)
    row.update({
        "effect_entropy": eff["effect_entropy"],
        "effects_pct": eff["effects_pct"],
        "dominant_slot_by_effect": eff["dominant_slot_by_effect"],
        "max_effect_pct": eff["max_effect_pct"],
        "effects_l2": eff["effects_l2"],
    })

    # ---- Write ----
    write_jsonl(jsonl_path, row)
    print(f"[✓] wrote: {jsonl_path}")

    # Print a tight human summary
    print("\n=== SUMMARY ===")
    if "attn_dist" in row:
        print(f"**mem_entropy**={row['attn_mem_entropy']:.3f}  **top2_mass**={row['attn_top2_mass']:.3f}")
    else:
        print(f"(no **attn_dist**) note: {row.get('attn_note','')}")
    print(f"**sim_mean_offdiag**={row['sim_mean_offdiag']:.3f}  **sim_max_offdiag**={row['sim_max_offdiag']:.3f}")
    print(f"**base_nll**={row['base_nll']:.4f}  **max_delta_nll**={row['max_delta_nll']:.4f} (slot {row['dominant_slot_by_nll']})")
    if isinstance(row.get("gradcorr", {}).get("ok"), bool) and row["gradcorr"]["ok"]:
        print(f"**gradcorr_mean_abs_offdiag**={row['gradcorr']['mean_abs_grad_corr_offdiag']:.3f}  leader={row['gradcorr']['grad_leader']}")
    else:
        print(f"(no **gradcorr**) reason: {row.get('gradcorr',{}).get('reason','')}")
    if isinstance(row.get("train_vs_rollout", {}).get("ok"), bool) and row["train_vs_rollout"]["ok"]:
        print(f"**KL(train→rollout)**={row['train_vs_rollout']['kl_train_to_rollout']:.4f}  max_shift_slot={row['train_vs_rollout']['max_shift_slot']}")
    else:
        print(f"(no **train_vs_rollout**) reason: {row.get('train_vs_rollout',{}).get('reason','')}")
    print(f"**effect_entropy**={row['effect_entropy']:.3f}  **max_effect_pct**={row['max_effect_pct']*100:.1f}% (slot {row['dominant_slot_by_effect']})")


if __name__ == "__main__":

## Важные технические моменты (чтобы не словить “тихий баг”)

- **`build_model_from_ckpt()`** — единственное место, которое нужно подогнать под твою репу.  
  **Технический термин:** **state_dict** — веса модели в PyTorch, которые грузятся через `load_state_dict`.
- **`collect_memory_stats`** — если у тебя уже есть **счётчики attention по слотам** в `memory_bank`, то оно заработает сразу.  
  **Технический термин:** **forward flag** — параметр вызова `model(x, flag=True)`, который включает сбор диагностик.
- **Gradient correlation** требует, чтобы **градиент реально доходил** до слотов. Если `memory_slots.grad is None` — значит у тебя либо **detach**, либо слоты не участвуют в loss.
  **Технический термин:** **gradient flow** — путь производных от **loss** до параметров.

# Почему нельзя просто “включить все регуляризаторы на максимум сразу”

1. **Градиенты дерутся**

2. **Симметрия убивает специализацию**
   Если слоты изначально похожи и ты сразу давишь “быть ортогональными + быть равномерно используемыми + быть стабильными”, модель может выбрать простейшее: “я вообще не буду их использовать” (это ровно то, что ты уже наблюдал: эффекты ~0.001–0.004).

* **PIT mean** ближе к **0.5**
* средняя signed‑ошибка one‑step ближе к 0

## Drift = накопленный дефокус

* Err@100/200/1000 падают
* рост ошибки по горизонту становится “мягче”

* **CRPS**
* **Err@h**
* **PIT mean/std**

- **DAG / compute graph** (граф вычислений) сам по себе не даёт смысла.
- Смысл появляется только если есть:
  1) **дифференцируемый сигнал** (в **loss**),
  2) который заставляет слот быть полезным именно как *тот* инвариант.

**Технические термины:**
- **learnable vectors** — обучаемые вектора-параметры (слоты).
- **aux_loss** — дополнительная часть функции потерь, которая задаёт поведение (семантику) модуля.
- **DAG / compute graph** — граф вычислений; смысл возникает только там, где есть **градиентный путь**.
- **gradient path** — путь, по которому **градиенты** доходят до параметров.

# Критичная поправка к твоей таблице
Ты пытаешься “втиснуть” **Q3-модули** в локальные **window stats**. Это частично работает, но есть опасность:

### Q3-инварианты — не все локальные
- **T0**, **A3-floor**, **RKHS-cap**, **Toeplitz barrier** — это конструкции уровня **операторов/символов**, а не просто “mean/std”.
- Локальные прокси можно сделать, но это будет **proxy semantics**, не исходная математика.

То есть **путь 1** (“навязать Q3 сверху”) возможен, но нужно честно назвать это:
> мы не “обучаем Q3”, мы обучаем **прокси Q3-сигналов**, которые статистически должны коррелировать с нужными модулями.

# Как модель “может” начать определять M0–M7: три уровня жёсткости

## Уровень 0: Post-hoc (минимальная жёсткость)
Оставляем слоты свободными → после обучения делаем **probe / attribution**:
- **ablation** каждого слота → как меняются метрики (**SFF**, **PIT**, **Err@h**, хвосты, автокорреляции).
- строим матрицу “слот → на что влияет”.

Плюс: не навязываешь ложную семантику.  
Минус: семантика может получиться “перемешанной”.

**Технические термины:** **probe**, **attribution**, **ablation**.

---

## Уровень 1: Weak supervision (то, что тебе реально надо)
Оставляем часть свободы, но вносим “мягкую разметку”:

- Первые 4 слота можно **не выбрасывать** — просто переименовать как **Calibration Slots** (они стабилизируют оптимизацию).
- Слоты 4–7 направляем на Q3-прокси, но **не как жёсткий регресс на один скаляр**, а как:
  - **multi-target**,
  - **ранжирование/контраст**,
  - **hinge constraints** (например, “cap не должен расти”).

Плюс: слоты начинают специализироваться, но не клинятся.  
Минус: надо грамотно подобрать цели.

---

## Уровень 2: Semantic supervision (жёстко “навязать Q3”)
То, что ты набросал `compute_q3_invariants(x)` — это именно оно. Работает, но риск:
- ты можешь научить модель **оптимизировать прокси**, а не реальную структуру (classic Goodhart).

# Что я бы сделал (рекомендация): **гибрид**, самый безопасный

### 1) Оставить текущие 4 статистики, но перестать называть их M0–M3
Переименуй в голове:

- **S0–S3 = calibration slots**: **mean/std/autocorr1/autocorr5**
- **M4–M7 = discovery slots**: туда уже Q3-прокси + свобода

Почему это важно: иначе ты сам себя обманываешь “мы уже учим M0–M3”, хотя реально учим “mean/std”.

---

### 2) Для M4–M7 задать не “один скаляр”, а **набор прокси-ограничений**
Твои кандидаты норм, но я бы чуть перестроил:

- **M4 (smoothness / ω)**: не `diffs.std`, а **spectral slope** на окне (FFT энергии по частотам)
- **M5 (Toeplitz / translation-ish)**: не просто `autocorr lag1`, а **профиль autocorr по лагам** (1..L) и штраф на “ломаность”
- **M6 (RKHS-cap / primes don’t scream)**: не `max(x)`, а **tail mass** (например, доля > q95) — max слишком шумный
- **M7 (spectral gap / rollout stability)**: прокси — **multi-step consistency**: ошибка предсказания на горизонте h (например, h=10,50) на том же окне

**Технические термины:** **FFT**, **spectral slope**, **tail mass**, **multi-step consistency**.

# Конкретный код: улучшенная версия твоего `compute_q3_invariants`

```python
import torch
import torch.nn.functional as F

def autocorr_profile(x, max_lag: int = 16):
    # x: [B,T]
    x0 = x - x.mean(dim=1, keepdim=True)
    x0 = x0 / (x0.std(dim=1, keepdim=True) + 1e-8)
    B, T = x0.shape
    ac = []
    for lag in range(1, max_lag + 1):
        ac_l = (x0[:, :-lag] * x0[:, lag:]).mean(dim=1, keepdim=True)
        ac.append(ac_l)
    return torch.cat(ac, dim=1)  # [B, max_lag]

def spectral_slope(x, eps: float = 1e-8):
    # crude: slope of log-power vs log-freq
    # x: [B,T]
    B, T = x.shape
    x0 = x - x.mean(dim=1, keepdim=True)
    X = torch.fft.rfft(x0, dim=1)  # [B, F]
    P = (X.real**2 + X.imag**2) + eps
    freqs = torch.arange(P.shape[1], device=x.device).float() + 1.0
    logf = torch.log(freqs).unsqueeze(0)  # [1,F]
    logp = torch.log(P)
    # linear regression slope: cov(logf,logp)/var(logf)
    logf_c = logf - logf.mean(dim=1, keepdim=True)
    logp_c = logp - logp.mean(dim=1, keepdim=True)
    slope = (logf_c * logp_c).mean(dim=1, keepdim=True) / (logf_c.pow(2).mean(dim=1, keepdim=True) + eps)
    return slope  # [B,1]

def tail_mass(x, q: float = 0.95):
    # share of mass above quantile
    # x: [B,T]
    thr = torch.quantile(x, q, dim=1, keepdim=True)
    return (x > thr).float().mean(dim=1, keepdim=True)

def compute_q3_proxies(x):
    """
    Return 8 scalars per batch (B,8).
    NOTE: These are **proxies**, not literal Q3 objects.
    """
    B, T = x.shape
    diffs = (x[:, 1:] - x[:, :-1]).abs()

    # S0..S3 (calibration) - keep if you want
    s0_mean = x.mean(dim=1, keepdim=True)
    s1_std  = x.std(dim=1, keepdim=True)
    s2_ac1  = autocorr_profile(x, max_lag=1)[:, :1]
    s3_ac5  = autocorr_profile(x, max_lag=5)[:, 4:5]

    # M4..M7 (discovery, Q3-inspired proxies)
    m4_omega_proxy = spectral_slope(x)                      # smoothness proxy (frequency decay)
    m5_toeplitz_proxy = autocorr_profile(x, max_lag=8).std(dim=1, keepdim=True)  # "shape roughness"
    m6_rkhs_proxy = tail_mass(x, q=0.95)                    # cap proxy (tails)
    m7_gap_proxy = diffs.mean(dim=1, keepdim=True)          # stability-ish (mean step size)

    return torch.cat([s0_mean, s1_std, s2_ac1, s3_ac5,
                      m4_omega_proxy, m5_toeplitz_proxy, m6_rkhs_proxy, m7_gap_proxy], dim=1)
```

Главное: это честно называется **proxies**.

# Теперь по сути: откуда параллели и почему они честно “прокси”, а не “Q3”

Ты сейчас спрашиваешь правильную вещь: **почему именно эти прокси соответствуют модулям Q3?**

Ответ жёсткий:

> Мы не “вывели” это строго. Мы сделали **операционализацию**: превратили каждую идею Q3 в измеримый сигнал на окне `x` (последовательность **spacings**), чтобы у модели был **градиентный канал**.

**Технические термины:**
- **операционализация** — перевод абстрактного свойства в измеримую метрику.
- **proxy** — приближённая метрика, которая коррелирует с нужным свойством, но не равна ему.
- **градиентный канал** — путь, по которому сигнал (loss) может заставить параметры модели вести себя нужным образом.

---

# Почему `m1 = hist_entropy(x)` можно связать с **A1′** (и где тут риск)

**A1′ (density)** в Q3 — это: “на каждом компакте генераторы **Fejér×heat** могут аппроксимировать любой тест из конуса”.

В ML-переводе это не про “энтропию значений” напрямую. Это про:

> “насколько окно содержит достаточно **разнообразия режимов**, чтобы словарь/генераторы могли покрывать пространство тестов”.

**Histogram entropy** — это грубый прокси “разнообразия”: если распределение `x` узкое/одномодальное → энтропия низкая; если много режимов/широкое покрытие → энтропия выше.

✅ Поэтому связь **правдоподобная**:  
**A1′ ≈ coverage/diversity** → `hist_entropy` как сигнал “покрытие режимов”.

⚠️ Но это НЕ эквивалентность:  
A1′ — про аппроксимацию тестовых функций, а `hist_entropy` — про распределение конкретной последовательности.

Если хочешь сделать прокси ближе к A1′, лучше:

- считать энтропию не по значениям `x`, а по **локальным паттернам** (например, по вектору `[x_t, x_{t+1}, …, x_{t+k}]` в кластеризованном пространстве), т.е. энтропия **режимов**, а не “амплитуд”.

# Теперь “почему остальные” — по одному, с логикой

## M0: `mean(x) - 1.0` как **T0**
**T0** — это про **нормировку/unfolding**, т.е. средний **spacing** после нормировки должен быть ~1.  
Так что `E[x] ≈ 1` — реально правильный якорь.

**Технический термин:** **unfolding** — нормировка спектра к средней плотности 1.

---

## M2: `max |dx|` как **A2 Lipschitz**
**A2** — про **устойчивость** Q к малым изменениям тестов (Липшицевость).  
Для данных это переводится в: “нет ли диких скачков в локальной геометрии окна”.  
`max|dx|` — прямой индикатор *самого плохого* скачка → хороший “охранник”.

**Технический термин:** **Lipschitz** — ограничение на максимальную скорость изменения.

---

## M3: `q1%` как **A3 floor**
**A3 floor** в Q3 — это нижняя граница символа/пола, а на уровне spacings это чаще всего проявляется как **level repulsion**: очень маленькие spacings редки.  
`q1%` (1-й перцентиль) — адекватный прокси “насколько близко к нулю подползает хвост”.

---

## M4: `mean|d2x|` как **smoothness**
В Q3 **smoothness / ω(·)** — это модуль непрерывности символа (**ω**), т.е. “насколько всё гладко/не рвано”.  
Во временном ряду “рваность” = “кривизна” = вторая разность.  
`mean|d2x|` — нормальный прокси “сколько у нас локальной кривизны”.

**Технический термин:** **modulus of continuity ω** — мера гладкости через максимум отклонений при малом сдвиге.

---

## M5: `half_window_divergence(x)` как **Toeplitz**
Toeplitz-идея — это **translation invariance**: свойства должны быть стабильны при сдвиге по окну.  
Если первая половина окна “не похожа” на вторую — translation invariance плохая.

Поэтому divergence между половинами (например, **KL** между гистограммами или расстояние между эмбеддингами) — хороший прокси.

**Технические термины:** **Toeplitz**, **translation invariance**, **KL divergence**.

---

## M6: `high_freq_energy(dx)` как **RKHS cap**
В Q3 **RKHS cap** ограничивает вклад “праймов”, что в сигнале выглядит как “не должно быть излишней высокочастотной возни/шума”.
Энергия высоких частот — естественный прокси “не кричит ли компонент”.

Важно: это **эвристика**, но она работает как “cap на резкие компоненты”.

**Технические термины:** **RKHS**, **cap**, **high-frequency energy**.

---

## M7: `local_rigidity(x)` как **spectral / Δ3**
**Δ3** (и родня) — это про **жёсткость спектра** на длинных масштабах: как сильно кумулятивные отклонения растут с длиной окна.  
Если ты строишь “локальную rigidity” (аналог Δ3 на коротком окне) — это прямой кандидат в “M7”.

**Технический термин:** **spectral rigidity Δ3** — мера отклонения от линейности счётчика уровней после unfolding.

# Главный твой вопрос: “может дать модели самой определить переменные?”

Да. И это как раз твой путь 2, но важно сделать его правильно:

## Что значит “модель сама определяет переменные”
Это значит:

1) мы не говорим “слот = mean”  
2) мы говорим “слоты должны стать **координатами**, которые:
   - (а) реально влияют на предсказание,
   - (б) устойчивы (не разваливаются в rollout),
   - (в) разделимы (не все одинаковые),
   - (г) интерпретируемы пост-фактум через probes”

**Технические термины:**
- **latent variables** — скрытые переменные/координаты.
- **disentanglement** — разъединение факторов.
- **probes** — диагностические модели, которые выявляют, что кодирует слот.

# Как сделать “свободу” без потери контроля (конкретный протокол)

### Шаг 1. Слоты свободны, но мы принуждаем их быть “хорошими координатами”
Не “mean/std”, а три общих регуляризатора:

- **Orthogonality** (слоты разные)
- **Non-collapse** (энтропия внимания на слоты не падает в ноль)
- **Rollout stability** (распределение использования слотов не меняется катастрофически в rollout)

Это не навязывает смыслы, но вынуждает систему создать **устойчивые регистры**.

### Шаг 2. Пост-фактум “снятие физики”
После обучения ты берёшь каждый слот и меряешь корреляции/влияния на:
- твои `m0..m7` прокси
- глобальные тесты (**SFF**, **Δ3**, **n-level** если есть)
- метрики предсказания (**Err@h**, **PIT**, **CRPS**)

И получаешь карту:
> “какой слот управляет чем”

### Шаг 3. Извлечение формулы
Когда слоты стали устойчивыми координатами, ты делаешь **symbolic regression** (типа PySR/спарс-формулы) уже на уровне:
- “слот → влияние на предсказание”
- “слот → корреляция с тестами”

И это реально путь к “математике/физике/геометрии”.

# Самое важное: не перепутать “прокси-инварианты” и “истинные переменные”

То, что ты перечислил (m0..m7) — это классный **панельный прибор**.  
Но настоящие переменные могут оказаться другими:

- фазовые сдвиги
- резонансные моды
- скрытые “операторные” координаты
- геометрия распределения контекста

# 1) Что реально означает “структура в трансформере”

## Что ты правдиво сказал
> “Если трансформер умеет предсказывать следующий ноль, значит в нём есть структура.”

Да — **в функциональном смысле**.

Но структура бывает **трёх принципиально разных типов**.

---

## Тип A — **табличное заучивание** (lookup / interpolation)

Модель может:
- выучить длинный контекст,
- научиться “угадывать следующий” **только внутри диапазона обучения**.

Признаки:
- отлично работает **in-distribution**,
- резко ломается:
  - на других масштабах,
  - на длинном rollout,
  - при небольшом шуме/перестановке.

👉 Это **НЕ формула**, это **интерполяция**.

**Технические термины (жирным):**
- **memorization** — заучивание примеров.
- **interpolation** — гладкая аппроксимация внутри обученного диапазона.
- **OOD failure** — провал вне распределения.

---

## Тип B — **эффективное правило** (implicit operator)

Модель не знает “формулу”, но реализует:
\[
\gamma_{n+1} \approx F(\gamma_{n-k},\dots,\gamma_n)
\]

Где **F** — сложный, неявный оператор, реализованный сетью.

Признаки:
- устойчивый rollout,
- работает на новых масштабах,
- ошибки растут **медленно**, не взрываются.

👉 Это уже **структура**, но **не аналитическая формула**.

**Технические термины:**
- **implicit operator** — неявный оператор.
- **functional approximation** — аппроксимация отображения между функциями.

---

## Тип C — **явная структура / координатизация** (то, что ты хочешь)

Это когда внутри модели появляются:
- **устойчивые координаты**,
- **моды**, **инварианты**, **регистры**,
- которые можно:
  - замерить,
  - выразить,
  - аппроксимировать формулами.

👉 Это единственный путь к **извлекаемой математике**.

# 3) Так есть ли “формула” в весах модели?

Очень важный момент:

## ❌ Формулы **НЕ хранятся** в весах

# 4) Зачем тогда Memory Slots? (ключевой момент)

- **latent variables** — скрытые переменные.
- **coordinate system** — система координат.
- **disentanglement** — разъединение факторов.

# 5) Почему “общие constraints” принципиально важны

Без constraints модель выберет **дешёвый путь**:
- всё зашьёт в backbone,
- слоты станут декорацией,
- формул извлечь будет нельзя.

**Constraints делают две вещи:**
1. **заставляют** модель использовать слоты;
2. делают слоты **стабильными регистрами**, а не шумом.

Ты это уже делаешь через:
- orthogonality,
- entropy,
- rollout stability,
- ablation sensitivity.

**Weights**/**параметры** — это просто “форма стекла линзы”: миллионы чисел, которые реализуют алгоритм.
Сколько параметров “ушло” на структуру? Нельзя честно ответить “вот 12% параметров про структуру”, потому что структура распределена по сети и не линейно локализована.

**Технические термины:**

* **Transformer** — сеть, которая учится “смотреть” на весь контекст через **attention**.
* **weights / параметры** — числа, которые задают поведение сети. Это не формула в виде текста, это реализация алгоритма.

---

## 2) Предсказывать следующий нуль ≠ “у модели есть формула для всех нулей”

Это прям ключ.

### Что означает успешный one-step prediction

Если модель хорошо предсказывает (s_{n+1}) по (s_{1:n}), это означает:

* она аппроксимировала **условный закон** следующего шага (в среднем по данным).

### Что НЕ следует из этого

Не следует, что:

* она знает “закрытую формулу” для (\gamma_n) для всех (n),
* или что она “решила RH”,
* или что она может “вычислить нули в принципе” без данных.

**Модель может быть сильной в условном продолжении процесса**, но это не то же самое, что **явная формула**.

**Технические термины:**

* **формула** — компактное проверяемое аналитическое выражение (или маленький алгоритм с доказуемыми свойствами).
* **условное распределение** — правило вида “что вероятно дальше при данном прошлом”.

---

## 3) Может ли модель “просто выучить нули и выдавать по номеру”?

В твоей постановке со spacings это обычно **не проходит**, если ты не оставил лазейку.

Чтобы “просто выдавать по номеру”, модели нужен **идентификатор позиции**:

* индекс (n),
* абсолютная высота (\gamma_n),
* или любой скрытый маркер “где мы в файле”.

Если вход — просто окно **spacings** без индекса, то “по номеру” выдать трудно: один и тот же локальный паттерн может встречаться в разных местах.

Но есть два реальных варианта читинга:

1. **утечка индекса** через датасет/сплит (например, всегда берем окна строго подряд и модель учит “место в файле” косвенно).
2. **локальная подгонка**: модель выучила супер-специфические статистики для твоего диапазона высот и ломается при переносе.

**Технические термины:**

* **memorization** (зазубривание) — модель “помнит ответы” вместо правила.
* **generalization** (обобщение) — модель выучила переносимое правило.

---

## 4) Как честно доказать, что это НЕ тупая зубрёжка (три теста)

Вот прям “железный набор”.

### Тест A: **Cross-height validation**

Учишь на одном диапазоне высот, тестишь на другом, максимально далёком.
Если качество держится — это уже не “табличка”.

**Cross-height validation** — проверка переноса на другой “космос” по (\gamma).

### Тест B: “анонимные окна”

Перемешиваешь окна так, чтобы модель не могла восстановить абсолютную позицию.
Если метрики почти не меняются — индекс не используется.

### Тест C: **Rollout** и “срыв фокуса”

Зубрёжка часто выглядит красиво на **teacher forcing** (когда всегда подсовываешь правильное прошлое), но разваливается на **rollout** (когда модель питается своими предсказаниями).
Если **drift** мал — это сильный аргумент, что внутри реально правило, а не таблица.

**Технические термины:**

* **teacher forcing** — на каждом шаге подаём истинные предыдущие значения.
* **rollout** — модель сама себя продолжает, и ошибка накапливается.
* **drift** — накопленный систематический уход при rollout.

---

## 5) Зачем нам “слоты” и как из них реально добывать формулы

Вот тут ты мыслишь очень правильно: **слоты = координаты решета**.

Идея такая:

1. **Transformer** держит структуру (обобщённые constraints).
2. **Memory tokens** (слоты) должны стать **наблюдаемыми регистрами**: “в каком состоянии линза сейчас”.
3. Затем мы строим “маленькую модель поверх слотов” и делаем **symbolic regression**.

### Почему слоты нужны

Потому что “формула” почти никогда не находится напрямую из 17.8M весов.
Формулу удобно искать в низкоразмерных координатах (слоты) → это как “сжать физику в параметры”.

**Технические термины:**

* **symbolic regression** (например **PySR**) — поиск компактной формулы, которая объясняет зависимость.
* **distillation** — обучить маленькую интерпретируемую модель, которая имитирует большую.

---

## 6) Откуда взялись параллели M0..M7 (и почему это не “придумано”)

Мы не утверждаем “это точно Q3”. Мы делаем **Q3-proxy** (наблюдаемые датчики), которые соответствуют *смыслу* компонентов Q3:

* **M0** (mean−1) — датчик “калибровки света” (нормировка unfolding).
* **M2/M4** (max jump, curvature) — датчики “дрожания/гладкости линзы”.
* **M3** (нижний квантиль) — датчик “floor: нет провалов”.
* **M5** (стабильность при кропе/сдвиге) — датчик “Toeplitz: не ломаться от пикселизации”.
* **M6** (высокочастотная энергия) — датчик “RKHS-cap: не пускать рябь”.
* **M7** (локальная rigidity) — датчик “spectral gap: фокус держится на дальнем масштабе”.

То есть это **сенсоры**, а не догма.

---

## 7) Важный апгрейд твоей цели

Ты сказал: “лучше всего — формулы, чтобы перепроверить”.

Супер. Тогда цель системы становится трёхуровневой:

1. **Predictor-level**: лучший предиктор (p(s_{t+1}\mid s_{1:t})) (MDN).
2. **State-level**: слоты = состояние линзы, которое объясняет bias/drift.
3. **Formula-level**: формула, которая приближает поведение слотов/или “следующий шаг” через слоты.

И вот это уже реально “математика-физика через ML”.

## 8) Два честных решения на твой вопрос “может там другие переменные важны”

Да, возможно. И самый честный способ это проверить:

* оставить часть слотов **якорными** (M0–M7 с Q3-proxy supervision),
* добавить 2–8 **свободных слотов** без семантики,
* после обучения сделать:
  **корреляции + ablation + symbolic regression** на свободных слотах.

Так модель “сама предложит переменные”, а ты их потом переведёшь в формулы и проверишь.

**Технические термины:**

* **ablation** — выключил слот → посмотрел, что сломалось.
* **free slots** — латенты без семантики, чтобы найти “непредвиденные параметры”.

### “Memory-first warmup”
- первые N шагов (например, 2k): **freeze backbone**, учим только memory (+ head)
- потом размораживаем всё.

Если после этого **Ablation Δ** вырастает — значит backbone раньше “съедал” задачу.

**Технические термины:** **freeze**, **warmup**, **capacity hijack**.

class SpacingNextDataset(Dataset):
    """
    Each item:
      x: [T]  (float)
      y: []   (scalar float) = next spacing
    """

    def __init__(self, spacings_1d: torch.Tensor, seq_len: int = 257):
        super().__init__()
        assert spacings_1d.dim() == 1
        assert seq_len >= 2
        self.s = spacings_1d.float()
        self.seq_len = seq_len
        self.T = seq_len - 1
        self.n = self.s.numel() - seq_len
        if self.n <= 0:
            raise ValueError("Not enough data for given seq_len.")

    def __len__(self) -> int:
        return self.n

    def __getitem__(self, i: int) -> Tuple[torch.Tensor, torch.Tensor]:
        seq = self.s[i : i + self.seq_len]      # [seq_len]
        x = seq[:-1].contiguous()               # [T]
        y = seq[-1].contiguous()                # []
        return x, y

# MDN loss (single-step)

def mdn_nll_1step(pi: torch.Tensor, mu: torch.Tensor, sigma: torch.Tensor, y: torch.Tensor, eps: float = 1e-8) -> torch.Tensor:
    """
    pi, mu, sigma: [B, K]
    y: [B]
    """
    sigma = torch.clamp(sigma, min=eps)
    y = y.unsqueeze(-1)  # [B,1]
    log_prob = -0.5 * (((y - mu) / sigma) ** 2 + 2.0 * torch.log(sigma) + math.log(2.0 * math.pi))  # [B,K]
    log_pi = torch.log(torch.clamp(pi, min=eps))
    log_mix = torch.logsumexp(log_pi + log_prob, dim=-1)  # [B]
    return -log_mix.mean()

@dataclass
class ModelConfig:
    n_layer: int = 6
    n_embd: int = 256
    n_head: int = 8
    dropout: float = 0.1

    seq_T: int = 256             # data length

class SimpleMDNHead(nn.Module):
    """
    Takes [B, D] and outputs MDN params [B,K].
    """
    def __init__(self, n_embd: int, n_mixtures: int):
        super().__init__()
        self.fc = nn.Linear(n_embd, 3 * n_mixtures)
        self.K = n_mixtures

    def forward(self, h: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        out = self.fc(h)  # [B, 3K]
        K = self.K
        pi_logits = out[:, :K]
        mu = out[:, K:2*K]
        log_sigma = out[:, 2*K:3*K]
        pi = F.softmax(pi_logits, dim=-1)
        sigma = torch.exp(log_sigma)
        return pi, mu, sigma


class SpacingMDNPostfix(nn.Module):
    """
    This is a thin wrapper around your existing transformer blocks.

    TODO: Replace the transformer internals with imports from your repo:
      - token embedding / input_proj
      - wpe positional embedding
      - blocks

      - memory_bank (returns learnable slots, shape [B,M,D])

    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.cfg = cfg
        self.n_memory_slots = cfg.n_memory_slots

        # ---- input proj: spacing scalar -> embedding
        self.input_proj = nn.Linear(1, cfg.n_embd)

        # ---- positional embedding
        self.wpe = nn.Embedding(cfg.block_size, cfg.n_embd)
        self.drop = nn.Dropout(cfg.dropout)

        # ---- transformer blocks
        # TODO: import your Block from repo
        # from model import Block
        # self.blocks = nn.ModuleList([Block(cfg) for _ in range(cfg.n_layer)])
        self.blocks = nn.ModuleList([nn.TransformerEncoderLayer(
            d_model=cfg.n_embd, nhead=cfg.n_head, dropout=cfg.dropout, batch_first=True
        ) for _ in range(cfg.n_layer)])

        self.ln_f = nn.LayerNorm(cfg.n_embd)

        # ---- memory slots (learnable)
        self.memory = nn.Parameter(torch.randn(cfg.n_memory_slots, cfg.n_embd) * 0.02)

        # ---- readout weights (optional learnable pooling)
        self.readout_weights = nn.Parameter(torch.zeros(cfg.n_memory_slots))

        # ---- MDN head (single step)
        self.mdn_head = SimpleMDNHead(cfg.n_embd, cfg.n_mixtures)

    def memory_bank(self, B: int, device: torch.device) -> torch.Tensor:
        # [B,M,D]
        return self.memory.unsqueeze(0).expand(B, -1, -1).to(device)

    def forward(self, x: torch.Tensor, slot_off: Optional[int] = None) -> Tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        """
        x: [B,T] spacings window
        output: pi, mu, sigma each [B,K]
        """
        B, T = x.shape
        device = x.device
        M = self.n_memory_slots

        mem = self.memory_bank(B, device)  # [B,M,D]
        if slot_off is not None:
            mem = mem.clone()
            mem[:, slot_off, :] = 0.0

        # data -> emb
        x = x.unsqueeze(-1)           # [B,T,1]
        x = self.input_proj(x)        # [B,T,D]

        # POSTFIX: [data..., mem...]
        h = torch.cat([x, mem], dim=1)  # [B,T+M,D]

        # positional encoding (length T+M)
        pos = torch.arange(0, T + M, device=device, dtype=torch.long)
        h = h + self.wpe(pos)
        h = self.drop(h)

        # transformer
        for blk in self.blocks:
            h = blk(h)
        h = self.ln_f(h)

        # memory hidden = last M
        mem_h = h[:, -M:, :]  # [B,M,D]

        # readout: weighted pool (learnable), safer than mean
        w = F.softmax(self.readout_weights, dim=0)  # [M]
        readout = (mem_h * w.view(1, M, 1)).sum(dim=1)  # [B,D]

        pi, mu, sigma = self.mdn_head(readout)  # [B,K] each
        return pi, mu, sigma

            if step % args.eval_every == 0:
                v = eval_nll(model, dl_va, device)
                payload = {
                    "model": model.state_dict(),
                    "config": cfg.__dict__,
                    "step": step,
                    "val_nll": v,
                }
                save_ckpt(out_dir / "last.pt", payload)
                if v < best_val:
                    best_val = v
                    best_step = step
                    save_ckpt(out_dir / "best.pt", payload)

                print(f"[eval] step={step} val_nll={v:.6f} best={best_val:.6f} @ {best_step}")

            if step >= args.max_steps:
                break
        if step >= args.max_steps:
            break

    print(f"[done] best_val_nll={best_val:.6f} best_step={best_step}")

## 1) Что добавить в `diagnose_memory_postfix.py` (самое важное)

### G) **Train→Rollout Drift** (не только KL)
В PREFIX у тебя KL мог быть “идеально 0”, потому что memory не была причинной. В POSTFIX надо мерить **накопление ошибки по горизонту**.

**Метрики:**
- **Err@h** для h ∈ {1, 10, 50, 200, 1000} (MAE/RMSE на spacing)
- **Bias drift**: средняя signed-ошибка на горизонте
- **Error growth slope**: slope ошибки vs h

**Почему это важно:** это главный тест “модель выучила **неявный закон** vs просто локально подогнала”.

**Технические термины:** **rollout**, **drift**, **error growth**.

---

### H) **Cross-height / Split-by-index test** (anti-table)
Ты сам боялся “выучил по номеру”. Для spacings это тоже может случиться через косвенные корреляции.

**Сделай в диагностике:**
- тест на **другом куске высот** (если у тебя есть разметка по диапазонам)
- или хотя бы **split by contiguous blocks**: train early, test late

**Метрика:** NLL/Err@h отдельно по блокам.

**Технические термины:** **distribution shift**, **cross-height validation**.

---

### I) **Slot→Data Attention Profile** (куда именно смотрят слоты)
Сейчас ты меряешь важность слота и градиенты, но нужно видеть **что именно он читает**:

- для каждого слота j: распределение внимания по позициям t ∈ [1..T]
- агрегат: **center-of-mass** внимания, **effective receptive field**

**Почему это важно:** покажет, стали ли слоты **специализироваться по масштабу** (например, один читает хвост окна, другой — последние 20 токенов).

**Технические термины:** **attention profile**, **receptive field**, **center-of-mass**.

---

### J) **Permutation / Slot-ID sanity**
У тебя раньше `use_slot_id=True`. В POSTFIX это меньше похоже на чит, но sanity нужен.

**Тест:**
- случайно **перемешай IDs слотов** на inference (или при eval)
- если всё рушится — модель использует ID как костыль, а не содержание.

**Технические термины:** **permutation test**, **slot identity**.

---

### K) **Gradient rank / PCA of slot grads**
У тебя mean grad corr ~0.9 раньше. Но даже если корреляция упадёт, нам нужно понять: слоты реально дают **k измерений** или всё равно 1–2.

**Метрики:**
- матрица градиентов G ∈ R^{M×D} (усреднённая по батчам)
- **rank surrogate**: сколько компонент PCA объясняют 90% энергии (r90)

**Технические термины:** **effective rank**, **PCA**, **intrinsic dimension**.

# 1) Multi-start — но умный, не “рандом ради рандома”

### ❌ Плохо
Запускать 100 сидов одинаково — это тупо дорого и малоинформативно.

### ✅ Правильно: **early probe + kill**
Ты уже почти это делаешь, просто формализуем.

**Протокол:**
1. Запускаешь, скажем, **N=8–16 сидов**.
2. Даёшь им **короткий прогрев** (например, 1k–2k steps).
3. Меряешь **ранние индикаторы**, не финальный NLL:
   - **Ablation Δ**
   - **Grad Corr**
   - **Err slope**
4. **Убиваешь 70–80%** запусков, которые:
   - не показывают рост Ablation Δ,
   - или grad corr остаётся высоким,
   - или сразу уезжают в overfit.
5. Оставшиеся 2–3 **докручиваешь** до early-stop.

👉 Это называется **successive halving / early stopping bandit**.

**Технические термины (важно знать):**
- **multi-start optimization**
- **successive halving**
- **early stopping bandits**

Ты уже *интуитивно* делаешь это, просто доведи до системы.

# 2) Warm-start из “хорошего” сида (ты почти это предложил)

Твой вопрос про:

- берёшь **s7 best.pt**
- слегка **перетасовываешь / шумишь** веса (очень слабо)
- запускаешь несколько прогонов с **меньшим lr**

- но дать шанс уйти в **ещё более глубокий минимум**.

**Технический термин:** **warm start**, **noise injection**.

### Вариант B: **Layer-wise warm start**

# 3) SWA / Weight Averaging — underrated, но очень в тему

Есть техника, которая **прямо создана для таких ландшафтов**.

### **SWA — Stochastic Weight Averaging**
Идея:
- вместо одного `best.pt`
- усреднять веса нескольких “хороших” чекпоинтов вдоль траектории

Почему это работает:
- сглаживает острые локальные минимумы,
- часто даёт **лучшее обобщение**, чем любой одиночный сид.

**Как применить у тебя:**
- во время E4 сохранять веса каждые, скажем, 200 шагов **после** выхода на плато
- усреднить 5–10 таких чекпоинтов
- прогнать диагностику

**Технические термины:**
- **SWA**
- **flat minima**
- **weight averaging**

Это особенно хорошо сочетается с **POSTFIX bottleneck**.

# prime_heat_bounds_arch_data: theorem-route patch plan

## Core diagnosis

The provided ARCH context already contains:
- `ArchHeatMajorant.prime_heat_bounds_arch_of_majorant`
- `PrimeHeatArchPiecewiseKernel.prime_heat_bounds_arch_of_core_tail_majorant`
- `PrimeHeatDigammaShift.a_star_eq_a_star0_sub_shift_series`
- `PrimeHeatDigammaShift.a_star_le_a_star_zero`

The live blocker is still:
- `axiom prime_heat_bounds_arch_data_from_data_legacy_axiom`
- `theorem prime_heat_bounds_arch_data := by exact ...legacy_axiom`

The numeric margin is extremely tight:
- target integral: `1.360378309969694`
- certificate constant: `1.360378581976`
- slack: about `2.72006306e-7`

That means a hand-written crude majorant is not realistic. The viable theorem-route is a generated **segment certificate majorant**.

## One missing item

A generated, checker-free theorem body for the segment certificate module:
- the local interval envelope lemmas for `|a_star|`
- and the finite exact integral bound proving
  `g_arch_seg_integral_le_target`

Without that certificate payload, the bridge lemmas cannot remove the legacy axiom.

## One workaround

Use the existing local file
`aristotle_input/prime_heat_bounds_arch_data_target.lean`
as the generation target, but have the local script emit a **stable checked module**
`BrangeHeatCert_2026_01_28_ArchBound.lean` containing the finished proof term.
Then patch `BrangeHeatCert_2026_01_28.lean` exactly as above.

This keeps the theorem-route kernel-safe, avoids checker-heavy load-bearing imports,
keeps all cert constants unchanged, and removes the axiom from
`#print axioms Q3.Proofs.PrimeCert.prime_heat_bounds_arch_data`.
